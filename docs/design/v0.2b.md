# v0.2b: closed-loop simulation, control, link impairment, and evidence

The exact technical contract of release v0.2b. Project identity, architecture
principles, evidence policy, capability phases, and the project invariants live
in [docs/engineering-plan.md](../engineering-plan.md), which outranks this file.
This file governs one release: equations, parameters, wire layouts, recurrences,
predicates, and proof gates. It claims nothing about any other release.

## How to read this document

Four classes of text, and no sentence is more than one of them.

**Normative.** Equations, constants, recurrences, data types, wire layouts,
protocols, state machines, acceptance predicates, proof gates, and the
identifiers they bind. This is the release contract. An implementation that
disagrees with it is wrong.

**Informative.** Rationale, rejected alternatives, cost estimates, and the
"changed from the prior draft" notes that say why a contract reads as it does.
Informative text explains the contract and never extends it. Appendix A is
informative in full.

**Design probe.** Numbers labelled "probe" come from a stdlib Python model of the
equations in this document, run before any of it was implemented, with the
command that produced each printed beside it. They justify design choices. They
are not release evidence, they are not published, and `docs/results.md` never
cites them. The shipped `sim/` regenerates every one of them at the capability
that owns it, and a probe number that the implementation contradicts is a defect
in this document, not in the implementation.

**Release evidence, which does not exist yet.** Every measured latency,
coverage, percentile, campaign pass rate, and timing comparison named here is a
target with a declared gate, not a result. None of it exists until the
implementation ships and the declared campaigns run on the qualified machine.
`README.md` and `docs/results.md` may state such a number only after capability 9
produces it.

## Architecture summary

Three operating modes, one binary, `--mode=harness|lockstep|freerun`, default
`harness`.

| | harness | lockstep | freerun |
|---|---|---|---|
| **workload** | the stand-in `Plant` in `src/main.cpp`, pinned by `tests/functional/test_harness_workload.py` | sim peer over UDP | sim peer over UDP |
| **clock** | `origin + n * period_ns` | none in the loop | `origin + n * period_ns` |
| **blocking in the cycle** | none | one `recv` per tick, by design | none |
| **sensor/actuator socket** | not opened | fd A, bound and connected | fd A, bound and connected |
| **command socket** | not opened | not opened | drain-owned |
| **ground telemetry sink** | not opened | not opened | with `--ground` |
| **timing histograms** | yes | never (`stats::LoopStats::record` is not called) | yes |
| **RNG** | none | sim-side | sim-side |
| **sweep levels** | L0 through L7 | none | L8 |
| **publishable timing** | yes, on qualified bare metal | no, refused by the gate | yes, on qualified bare metal |

Those three strings are the whole runtime mode enum. There is no fourth mode.

The nonblocking rule is scoped to the modes that make a timing claim.
`run_harness` and `run_freerun` obey it: no blocking syscall inside the control
cycle, with the absolute-deadline `clock_nanosleep` at the cycle boundary as the
scheduling boundary rather than blocking work inside the measured path.
`run_lockstep` blocks on exactly one receive per transaction, by design, because
lockstep produces no timing evidence and `discipline_problem` refuses its
summaries as timing evidence. That receive lives in the lockstep translation
unit and appears in no path `run_freerun` or `run_harness` can reach;
`scripts/check_nonblocking.py` asserts both halves of that sentence.

Changed from the prior draft: three modes rather than two, `harness` is the
default, and the deletion of the stand-in `Plant` is withdrawn, because mandate
correction 1 requires the published L0 through L6 workload to keep its meaning.

Free-run and lockstep run three processes on one host over 127.0.0.1. Framing v1
is frozen and is defined in this document under "Wire and transport"; nothing
here changes the outer frame.

| process | fd | binds | connects to | carries |
|---|---|---|---|---|
| vehicle `build/tvc_harness` | A, control thread | `--sensor-port` (production 24000) | the source of the first sensor datagram | recv sensor (type 4), send actuator (type 5) |
| sim `python3 -m sim.run_sim` | S | `--bind-port` (production 24001) | `--vehicle=HOST:PORT` | send sensor, recv actuator |
| vehicle drain thread | B | `--command-port` (production 24002) | none | recv command (type 2), send ack (type 3) by `sendto`; free-run only |
| vehicle drain thread | C | none | `--ground=HOST:PORT` | send control records (type 6) |
| station `python3 -m ground.station` | T | `--telemetry-port` (production 24003) | none | recv control records |
| station | G | ephemeral, always `bind(0)` | none | send command, recv ack |

The conceptual flow stays distinct at every stage, even where v0.2b idealizes
one:

```
truth state
  -> sensor model            ideal-v1
  -> observation
  -> impaired sensor link    link.loss.up
  -> controller              pid-v1
  -> requested actuator command
  -> impaired command link   link.loss.down, delay FIFO
  -> actuator model          ideal-angle-v1
  -> applied actuator state
  -> plant                   pitch-frozen-flight-v1, frozen-flight-v1
```

Where each boundary lives in code:

| boundary | v0.2b implementation | file |
|---|---|---|

What ships: the simulation package `sim/`, the PID in C++ with a bit-exact

## Plant model

A one-degree-of-freedom rigid-body pitch model at a frozen flight condition.
Model id `pitch-frozen-flight-v1`.

Changed from the prior draft: the inverted-pendulum analogy is withdrawn,
because the destabilising moment here is aerodynamic and proportional to angle
of attack and dynamic pressure, not gravitational, and the analogy invites a
reader to expect a gravity torque, a pivot, and a stable hanging equilibrium,
none of which the model contains (mandate correction 3).

### Frame, states, and signs

The maneuver plane is the plane containing the frozen velocity vector. One rigid
body rotates about its own center of gravity in that plane. Every angle in this
document is measured from one fixed reference axis in that plane, `x_ref`, which
is inertial and does not move with the vehicle or with the flow.

| symbol | meaning | unit | sign convention |
|---|---|---|---|
| `theta` | body pitch attitude, the angle from `x_ref` to the body axis | rad | positive is nose up from `x_ref` |
| `gamma` | flight-path angle, the angle from `x_ref` to the vehicle velocity vector | rad | positive is velocity above `x_ref`; frozen at `gamma_0 = 0` for the whole episode |
| `omega` | body pitch rate, `d(theta)/dt` | rad/s | positive is nose-up rotation |
| `alpha` | angle of attack, `theta - gamma`, the angle from the velocity vector to the body axis | rad | positive when the nose is above the flight path |
| `delta` | applied gimbal angle | rad | positive deflection produces a nose-down moment |
| `tau_d` | scheduled disturbance torque | N*m | positive is nose up |

Both `theta` and `gamma` are measured from the same fixed axis, so
`alpha = theta - gamma` is a subtraction of two angles in one frame and holds
whatever `gamma` does. v0.2b then fixes `gamma = gamma_0 = 0`, so `alpha =
theta`. Changed from the prior draft twice: `alpha` was defined against the
relative wind, which is anti-parallel to the velocity vector and gave
`alpha = theta - gamma + pi`; and `theta` was defined from `gamma_0` rather than
from a fixed axis, which subtracts the flight-path angle twice as soon as
`gamma` is allowed to move in `pitch-frozen-flight-v2`.

Positive gimbal direction: the nozzle pivot sits `L = 0.45 m` behind the center
of gravity, and a positive `delta` swings the thrust vector so its lateral
component acts upward at that station. The moment about the center of gravity is
then `-F*L*sin(delta)`, nose down. A positive attitude error therefore calls for
a positive gimbal command, and every controller gain is positive with no leading
minus for two implementations to disagree about.

Aerodynamic moment sign: positive, destabilising. The center of pressure sits
ahead of the center of gravity, so a positive `alpha` puts the normal force above
the axis ahead of the CG and pitches the nose further up. The coefficient `k_a`
is positive and the term enters `+k_a * alpha`.

Thrust-vector moment sign: negative in `delta`, `-F*L*sin(delta)`, as above.

Disturbance sign: positive `tau_d` is a nose-up moment. Scenarios express a gust
as an equivalent gust angle of attack `alpha_g` (rad) and the scenario evaluator
resolves it to `tau_d = k_a * alpha_g` before the plant sees it. Under the v1
linear aerodynamic law those two are the same number, so a gust is a lateral wind
of `V * alpha_g`: `alpha_g = 0.20` is a 12.0 m/s lateral gust, `alpha_g = 0.45`
is 27.0 m/s (probe).

Gravity does not appear. It acts at the center of gravity and produces no moment
about it, in any orientation, so a rotational one-degree-of-freedom model has no
place to put it.

### Angle of attack reduces to the modeled pitch error

    alpha = theta - gamma,   gamma == gamma_0 == 0   =>   alpha == theta

The conditions under which that holds:

1. The model has no translational degree of freedom, so the velocity vector
   cannot rotate and `gamma` cannot change. This is the frozen flight condition,
   and it is an assumption, not a derivation.
2. The setpoint is `theta_sp = gamma_0 = 0` in every v0.2b scenario, so the
   modeled pitch error `e = theta - theta_sp` and the angle of attack are the
   same number. Flying a nonzero `theta_sp` under this model would command a
   nonzero trim angle of attack, which is why v0.2b holds `theta_sp` at zero.
3. Rate-induced local flow angle at the center of pressure, `omega * l_arm / V`,
   is dropped. That term is aerodynamic pitch damping.

`gamma_0 = 0` is a compile-time zero and does not appear in the recurrence; the
run record carries it as a resolved parameter.

Freezing `gamma` is an assumption, and the rotation it discards is not zero.
`pitch-frozen-flight-v1` is an attitude-loop model at a fixed flight condition:
v0.2b makes no trajectory claim, no drift claim, and no claim about where the
vehicle goes, and no acceptance clause reads `gamma`. Appendix A sizes the
discarded rotation from this model's own parameters; that estimate is
informative and no contract depends on it.

The dropped damping term is stabilising, so leaving it out makes the control
problem harder. Its size: `k_a * l_arm / V = 0.039 N*m` per rad/s against the
controller's `J * b * KD = 8.343 N*m` per rad/s, 0.47% (probe). Setting the
pitch-damping derivative to zero is worth 0.47% of the closed-loop damping, and
stating that is cheaper than carrying a coefficient nobody sourced.

### Aerodynamic term

Choice: **linear aerodynamic stiffness `k_a * alpha`, `k_a` in N*m/rad.**

Changed from the prior draft, which multiplied a coefficient in N*m/rad by
`sin(theta)` (mandate correction 3). The linear form is the one consistent with
the coefficient's own provenance: a normal-force curve slope `C_N_alpha` is a
derivative at `alpha = 0`, so using it linearly is exactly what it supports.
Picking `M_a0 * sin(alpha)` instead would advertise a nonlinear normal-force
curve that no source in this project provides.

The downside: the term carries no normal-force nonlinearity and no stall. The
loss-of-control declaration at `|theta| > 0.30 rad` (17.2 deg) keeps the plant
inside a region where a linear slender-body `C_N_alpha` is at least arguable, and
17.2 deg is already at the edge of that.

### Where `k_a` comes from

Every input is a synthetic design parameter. There is no validated vehicle
behind any of them.

| input | symbol | value | unit | class |
|---|---|---|---|---|
| air density | `rho` | 1.225 | kg/m^3 | synthetic design parameter, sea-level standard |
| airspeed | `V` | 60.0 | m/s | synthetic design parameter |
| body diameter | `d` | 0.10 | m | synthetic design parameter |
| reference area | `S` | 0.0078539816 | m^2 | derived, `pi*d^2/4` |
| dynamic pressure | `q` | 2205.0 | Pa | derived, `0.5*rho*V^2` |
| normal-force slope | `C_N_alpha` | 2.0 | 1/rad | synthetic design parameter, slender-body value referenced to `S` |
| CG station from the nose | `x_cg` | 0.60 | m | derived, uniform slender body of length 1.2 m |
| CP station from the nose | `x_cp` | 0.34 | m | synthetic design parameter, chosen last |
| moment arm | `l_arm` | 0.26 | m | derived, `x_cg - x_cp` |

Arithmetic (probe, `python3 probe.py numbers`):

    q       = 0.5 * 1.225 * 60.0^2            = 2205.0 Pa
    S       = pi * 0.10^2 / 4                 = 0.0078539816 m^2
    q*S     = 2205.0 * 0.0078539816           = 17.318030 N
    q*S*C_N_alpha                             = 34.636059 N/rad
    k_a     = 34.636059 * 0.26                = 9.005375 N*m/rad
    k_a of record                             = 9.0 N*m/rad

`l_arm` is the parameter chosen last, so that `k_a` lands on a round
9.0 N*m/rad and the open-loop unstable pole lands on a round 5.0 rad/s. The
rounding from 9.005375 to 9.0 is 0.06%. That is an inversion, not a derivation,
and this document calls it one.

The honest caveat: `x_cp` was inverted from a target, so `k_a` is calibrated to
nothing. It is a synthetic design parameter that makes a demonstration work, this
document says so where the number appears, and no claim in v0.2b about vehicle
behavior rests on it. Appendix A works one external estimate of the same
quantity through in full, as informative text and outside every contract here.
The modeling invariant covers the future: a sourced airframe becomes
`pitch-frozen-flight-v2` with its own goldens, and no v0.2b evidence is
reinterpreted under it.

### Parameters of record

| symbol | value | unit | basis |
|---|---|---|---|
| `m` | 3.0 | kg | synthetic design parameter |
| `L_body` | 1.2 | m | synthetic design parameter, uniform slender body, 0.10 m diameter |
| `J` | 0.36 | kg*m^2 | derived, `m*L_body^2/12` |
| `F` | 60.0 | N | synthetic design parameter, thrust-to-weight 2.04 |
| `L` | 0.45 | m | synthetic design parameter, nozzle pivot to CG |
| `F*L` | 27.0 | N*m | derived, one constant in code (`FL`) |
| `k_a` | 9.0 | N*m/rad | derived and rounded, above; carried in `Environment.k_a` |
| `DELTA_MAX` | 0.12 | rad | gimbal stop, kept from `src/main.cpp:81` |
| `dt` | `1.0/500.0` | s | the measured loop rate, computed as that division |

Derived, all probe numbers from `python3 probe.py numbers`: `a = k_a/J =
25.0 s^-2`, unstable pole 5.0 rad/s, doubling from rest in 0.263 s (132 ticks).
`b = F*L/J = 75.0 s^-2`. Maximum control torque `F*L*sin(0.12) = 3.232230 N*m`.
Static balance angle `theta_tip = F*L*sin(DELTA_MAX)/k_a = 0.359137 rad`.

Changed from the prior draft: `theta_tip` moves from 0.3673 rad to 0.3591 rad,
because the balance condition under a linear aerodynamic term is
`k_a*theta = F*L*sin(delta_max)` rather than `M_a*sin(theta) =
F*L*sin(delta_max)` (mandate correction 3). The loss-of-control declaration stays
at 0.30 rad, now 0.059 rad below static balance instead of 0.067.

Constant within an episode, stated because "rocket" invites the opposite
assumption: thrust, mass, inertia, dynamic pressure, `k_a`, and the flight-path
direction. No gain scheduling. One axis.

The largest thing this freezes is dynamic pressure. At `F = 60 N` and
`m = 3.0 kg` the axial acceleration is at least 10.2 m/s^2, so 20 s of real
flight would take `V` past 260 m/s, `q` past 19x its frozen value, `k_a` past
170 N*m/rad and the open-loop pole past 21 rad/s (probe: `python3 probe.py
numbers`). `pitch-frozen-flight-v1` is a fixed-condition attitude model
evaluated over 20 s of simulated time, not a trajectory; a varying flight
condition is `pitch-frozen-flight-v2` with its own goldens, and `Environment` is
where its `k_a` stops being constant.

### Plant recurrence, exactly as coded

Semi-implicit (symplectic) Euler, one step per control period, 1:1 with the
500 Hz tick, zero-order hold on the applied gimbal across the period.

    # inputs: truth (theta_n, omega_n), actuator.applied (delta_n),
    #         env.k_a, dist.tau_d, dt
    alpha     = theta_n                                       # gamma frozen at 0
    tau       = env.k_a * alpha - FL * psin(delta_n) + dist.tau_d
    omega_dot = tau / J
    omega_n1  = omega_n + omega_dot * dt
    theta_n1  = theta_n + omega_n1 * dt

`omega_dot` is the angular acceleration. Changed from the prior draft, which
called it `alpha`: `alpha` now means angle of attack and nothing else (mandate
correction 3). Changed again from the physics area's draft, which read the
module constant `K_A` while its own input list named `env.k_a`: the plant reads
`env.k_a` and `dist.tau_d` from its arguments, and `sim/plant.py` defines no
`K_A`, so the `frozen-flight-v1` identifier and the environment bump rule govern
a value the plant actually reads.

`dt = 1.0/500.0`, computed as that division in both languages,
`0x1.0624dd2f1a9fcp-9`. No substeps. Measured on the prior draft's probe:
S2-gust peak `|theta|` is 0.066094763132 at 1 substep and 0.066549645448 at 8, a
0.7% difference on the peak and 0.3% of the 0.15 rad pass threshold, with
identical settling time. Substepping adds a place for two implementations to
disagree and buys nothing measurable.

### The sine and its domain

The vehicle and the sim use a fixed 7th-order odd polynomial rather than libm
`sin`, so a golden does not depend on the libm build:

    x2 = x*x
    psin(x) = x * (1.0 + x2 * (C1 + x2 * (C2 + x2 * C3)))
    C1 = -1.0/6.0    C2 = 1.0/120.0    C3 = -1.0/5040.0

Coefficients are written as those divisions, never as decimals. Changed from the
prior draft: `psin` is applied to `delta` only, never to `theta`, because the
aerodynamic term is linear (mandate correction 3). Its argument is bounded by the
gimbal stop, `|delta| <= 0.12`, where the polynomial differs from `sin` by
1.4e-14 absolute (probe). The prior draft's argument that the 0.30 rad
loss-of-control angle exists to keep `theta` inside the `psin` domain is
withdrawn: the domain constraint is now satisfied by the actuator's own stop, and
0.30 rad is a control decision justified by its distance from static balance and
nothing else.

`sin(delta)` stays rather than being linearised to `delta`: the lateral component
of a gimballed thrust vector is exact geometry, and keeping it costs one
polynomial whose argument can never leave a range 4x inside its accuracy budget.
Linearising would differ by 0.24% at the stop (probe) and would leave the model
with no geometric content at all.

Why the no-libm rule is not optional, measured on the prior draft's sweep: over
200,000 points in [-0.5, 5.5), Apple arm64 libm and glibc x86-64 `math.sin`
disagree on 7,068 points (3.53%); the fixed odd polynomial and a 1,000-step plant
integration produced identical bits on Mac arm64, Linux arm64 and Linux x86-64.
`tests/unit/test_sim_purity.py` greps `sim/` for `import math`, `from math`,
`numpy`, `**` and transcendental names and fails on a hit.

Floating-point assumption of record: binary64, round-to-nearest-even, no
contraction, on x86-64 or aarch64.

### Data types

Units are part of the type. Every angle is rad, every rate rad/s, every torque
N*m, every time step s.

    # sim/types.py
    class TruthState(NamedTuple):
        theta: float          # rad,   body pitch attitude from gamma_0
        omega: float          # rad/s, body pitch rate

    class Observation(NamedTuple):
        tick: int             # sim tick the sample was taken at
        theta: float          # rad
        omega: float          # rad/s
        valid: bool           # SAMPLE_VALID set and both fields finite

    class ActuatorCommand(NamedTuple):
        tick: int             # the sensor tick this command answers
        delta: float          # rad, requested gimbal angle, clamped to +-DELTA_MAX

    class ActuatorState(NamedTuple):
        applied: float        # rad, the applied gimbal angle the plant integrates

    class Environment(NamedTuple):
        k_a: float            # N*m/rad, aerodynamic stiffness at the frozen condition

    class Disturbance(NamedTuple):
        tau_d: float          # N*m, scheduled disturbance torque, positive nose up

    def step(truth: TruthState, actuator: ActuatorState, env: Environment,
             dist: Disturbance, dt: float) -> TruthState

`Environment` has one field. Keep the type anyway: it is what stops the plant
signature collapsing into a list of loose doubles, and it is where a variable
dynamic pressure lands in `pitch-frozen-flight-v2`. The resolved provenance
values (`rho`, `V`, `S`, `C_N_alpha`, `x_cg`, `x_cp`, `l_arm`, `q`) go in the run
record's parameter block, not in `Environment`: they are inputs to deriving
`k_a`, not to evaluating the moment law.

`Disturbance` carries a torque, not a gust angle, so the plant signature stays
independent of how a scenario chose to express the disturbance.

The vehicle constructs exactly two of these, and `src/model_types.hpp` defines
exactly those two:

    struct Observation {
        std::uint64_t tick;   // sim tick the sample was taken at
        double theta;         // rad
        double omega;         // rad/s
        bool   valid;         // SAMPLE_VALID set and both fields finite
    };

    struct ActuatorCommand {
        std::uint64_t tick;       // the sensor tick this command answers
        std::uint64_t veh_tick;   // vehicle cycle index n
        double        delta;      // rad, requested, clamped to +-DELTA_MAX
    };

`TruthState`, `ActuatorState`, `Environment` and `Disturbance` are Python-only in
v0.2b. Their C++ shapes are the four Python records field for field with `double`
members, and this document is the contract a C++ plant must match when Phase III
writes one. They are not compiled into v0.2b, because an unused struct is
speculative code and the simulation-kernel invariant is satisfied by the Python
plant being callable without UDP, files, or a clock.

These are internal model types and are not a wire format. `Observation` and
`ActuatorCommand` are what a decoded `sensor_v1` or `actuator_v1` payload
becomes.

## Actuator boundary

Three concepts stay distinct:

    requested actuator command  ->  actuator state  ->  applied gimbal angle  ->  plant

- **Requested actuator command.** What the controller computed and put on the
  wire, `ActuatorCommand.delta`, already clamped to `+-DELTA_MAX` because the
  anti-windup logic needs a saturation signal that agrees with the actuator's
  limit.
- **Actuator state.** What the hardware is doing, `ActuatorState`. It persists
  across ticks and it is the only place hold behaviour lives.
- **Applied gimbal angle.** `ActuatorState.applied`, the single number the plant
  integrates. There is no separate `AppliedGimbal` type: a one-field wrapper
  around a named field with a declared unit adds nothing.

The plant never sees a requested command. The controller never sees an applied
angle.

### PHY-1 ruling: model A, ideal angle-limited

**The actuator ships as `ideal-angle-v1`, the ideal angle-limited model. PHY-1
is closed and does not go to the owner.**

The v0.2b engineering claim is that a deterministic closed loop survives declared
packet loss and runs inside a real-time budget on qualified hardware. Nothing in
that claim depends on gimbal dynamics. The evidence: a 4 rad/s slew limit passes
the same 400/400 campaign, moves the worst `p = 0.30` peak from 0.0750 to 0.0841,
and leaves the 13-tick delay margin unchanged, while moving every golden. Under
the identifier grammar in `docs/engineering-plan.md` the later swap is a version
change, not an architecture change, so the simplest model that supports the claim
ships now. Changed from the prior draft, which returned this as an open decision
before the probe existed.

Because model A changes no dynamics relative to the prior draft's plant, no
re-tune, no new delay analysis, and no new loss campaign is forced by the
actuator choice. The re-runs below exist because the aerodynamic term changed.

### Actuator update, exactly as coded

    # ideal-angle-v1. `arriving` is the requested gimbal angle that reaches the
    # actuator this tick, or None when no actuator frame applies: downlink loss,
    # or the delay FIFO yields nothing.
    def step(state, arriving, dt):
        if arriving is None:
            return state                      # hold
        c = arriving
        if c >  DELTA_MAX: c =  DELTA_MAX
        if c < -DELTA_MAX: c = -DELTA_MAX
        return ActuatorState(applied=c)

The hold is here, and only here. Changed from the prior draft, whose lockstep
step G and free-run step 2 held the *requested* command upstream
(`requested_k = requested_{k-1}`) and prefilled the delay FIFO with `0.0`, which
made this branch unreachable and reduced `ideal-angle-v1` to the identity map.
Measured bit-neutral over 50 seeds of S2-gust at `p` in {0, 0.30} and `D` in
{0, 1}: max `|theta|` difference 0.000e+00 and peak difference 0.000e+00, because
both forms deliver the last non-lost command delayed by `D` and `applied` starts
at 0.0 (probe: `python3 probe.py holdvar`). Under the design of record the hold
branch is taken 149,639 times at `p = 0.30, D = 0` and 149,623 times at `D = 1`
over those 50 seeds, so the hold register is what the loss campaign exercises.

The clamp is authoritative here, not in the controller. The controller clamps to
the same constant, so the clamp never binds and `applied == requested` on every
tick a command arrives in every v0.2b run; if they ever disagree the actuator
wins and both numbers are in the record. `dt` is in the signature and unused by
`ideal-angle-v1`; it is what a rate- or state-based model needs, and leaving it
out would change the interface when the model changes.

### The replacement interface

A sourced first- or second-order actuator replaces `ideal-angle-v1` by providing:

    actuator.model_id                  -> str, recorded in replay.json and the golden manifest
    actuator.initial()                 -> ActuatorState
    actuator.step(state, arriving, dt) -> ActuatorState
    state.applied                      -> float, rad, the only field the plant reads

That is the whole contract, and it is the only actuator signature in this
document. Changed from the prior draft, which carried four incompatible forms
across the physics and execution sections, including a two-return `step` and a
separate `actuator.applied(...)`. `actuator.applied` is deleted. Every call site
reads `act_next = actuator.step(act, arriving, dt)` and then
`applied_k = act_next.applied`.

Plant integration reads `state.applied` and nothing else, so it does not change
on a swap. The controller emits `ActuatorCommand` and never sees actuator state,
so controller interfaces do not change. Scenarios name an actuator model id and
its resolved parameters, so scenario architecture does not change. What does
change on a swap: `ActuatorState`'s field list (a slew-limited model adds
`target`), the model id, and therefore every golden, which is what the modeling
invariant requires.

### What model B would cost, measured

and `applied` moves toward `target` by at most `rate * dt` per tick, then clamps.
It is not a first-order actuator and this document never calls it one; it has no
lag, no bandwidth, and no dynamic state beyond the position it has reached.

## Sensor observation

**No sensor noise in v0.2b. PHY-2 is closed.**

v0.2b uses an ideal sensor observation model, id `ideal-v1`: the observation
carries the truth state's `theta` and `omega` unchanged, unless the sample is
lost, stale, malformed, or non-finite. Those four are link and transport
effects, not sensor effects, and they are the only ways an observation departs
from truth in this release.

Truth state and sensor observation stay distinct representations even where their
numeric values are identical. `TruthState` has no tick and no validity;
`Observation` has both, because a receiver has to know which tick it is looking
at and whether it may read the fields. Nothing in the vehicle ever constructs a
`TruthState`, and nothing in the plant ever reads an `Observation`.

Deterministic quantisation, bias, noise, sampling effects, and state estimation
are Phase III model-fidelity work and each creates a new sensor model version.

The derivative filter stays in the controller even though there is no noise for
it to reject. It is structure, not tuning, today; adding it later would move
every golden.

## Controller

Parallel PID, `pid-v1`, derivative on the measured rate (the sensor's `omega`,
never a finite difference of `theta`), error measurement minus setpoint. The
integral state is carried in output units (rad of gimbal) so `KI*dt` folds into
one constant and the integral limit is stated against the actuator range.

### Gains and limits

| constant | value | hex | unit |
|---|---|---|---|
| `KP` | 3.277 | `0x1.a374bc6a7ef9ep+1` | rad/rad |
| `KI` | 7.68 | `0x1.eb851eb851eb8p+2` | 1/s |
| `KD` | 0.309 | `0x1.3c6a7ef9db22dp-2` | s |
| `KI_DT` | 0.01536 | `0x1.f75104d551d69p-7` | rad per rad |
| `BETA_D` | `1.0/3.0` | `0x1.5555555555555p-2` | |
| `DELTA_MAX` | 0.12 | `0x1.eb851eb851eb8p-4` | rad |
| `I_MAX` | 0.12 | `0x1.eb851eb851eb8p-4` | rad |
| `THETA_SP` | 0.0 | `0x0.0p+0` | rad |

Changed from the prior draft: the derivative filter coefficient `ALPHA_D` is
renamed `BETA_D`, because `alpha` is now angle of attack and this document uses
one name per thing (mandate correction 3). Value, position in the packed
constants, and therefore the digest are unchanged.

`KI * DT` gives `0x1.f75104d551d69p-7`; `KI / 500.0` gives
`0x1.f75104d551d68p-7`, one ulp lower (probe). The digest below catches that
transcription. `I_MAX = DELTA_MAX` so the integral can trim any disturbance the
gimbal can hold and never demand more; 0.06 left a steady-state error under a
sustained gust above 50% authority.

### Discrete update, exactly as coded

This block is the tier-1 bit-exactness contract and is stated here rather than
deferred, because `docs/design/v0.2b.md` is the only contract the control
capabilities have. Every intermediate is named, every sum is parenthesized, no
operation beyond `+ - * /` and comparison appears. It runs only on a tick with a
fresh sensor sample.

    KI_DT         = KI * DT
    NEG_DELTA_MAX = -DELTA_MAX
    NEG_I_MAX     = -I_MAX

    # per fresh sample (theta_n, omega_n)
    e      = theta_n - THETA_SP
    d      = d_prev + BETA_D * (omega_n - d_prev)
    i_cand = i_state + KI_DT * e
    if (i_cand >  I_MAX)     i_cand =  I_MAX
    if (i_cand <  NEG_I_MAX) i_cand =  NEG_I_MAX
    u_unsat = (KP * e + i_cand) + KD * d
    sat_hi  = (u_unsat >  DELTA_MAX)
    sat_lo  = (u_unsat <  NEG_DELTA_MAX)
    u       = sat_hi ? DELTA_MAX : (sat_lo ? NEG_DELTA_MAX : u_unsat)
    hold    = (sat_hi && e > 0.0) || (sat_lo && e < 0.0)
    if (!hold) i_state = i_cand
    d_prev     = d
    last_delta = u
    emit u

Three binding details, because the constants digest pins the seven values and
their pack order and cannot catch a reassociation:

1. the filter is `d_prev + BETA_D*(omega - d_prev)`, never the algebraically
   equal `(1-BETA_D)*d_prev + BETA_D*omega`;
2. the three-term sum associates `(KP*e + i_cand) + KD*d`, never
   `KP*e + (i_cand + KD*d)`;
3. the clamp applies to `i_cand` before it enters `u_unsat`, never to `u_unsat`.

`i_state` and `d_prev` update only on this path, so an outage of `s` ticks
advances the integrator by one increment, not `s`. Measured on the prior draft's
probe: scaling by `s` changes nothing at `p = 0.30` and costs one pass at
`p = 0.50`.

Anti-windup is conditional integration: freeze `i_state` when the output is
saturated and the error pushes further into it, which is the `hold` line. No
back-calculation gain. Measured on S3-kick, recovery defined as the last tick
with `|theta| > 0.02` from t = 0: conditional 0.244 s, `I_MAX` clamp only
0.626 s, neither 0.818 s.

Non-finite rejection: a sensor payload whose `theta` or `omega` is not finite is
not consumed. The cycle follows the staleness ladder, the record sets flags bit7
NONFINITE_REJECTED, and the `link` summary block counts `discarded_nonfinite`.
Tested in `tests/cpp/control_tests.cpp`.

Derivative filter: `BETA_D = 1/3`, pole `z = 2/3` (equivalent tau 4.9 ms,
203 rad/s); phase cost at the 24.2 rad/s crossover 5.5 deg. The filter state does
not update on a stale tick.

### Tuning and delay margin

1. Linearize: `theta_ddot = a*theta - b*delta`, `a = 25.0`, `b = 75.0`. The
   corrected aerodynamic term linearises to the same thing at the origin, so the
   tuning plant is unchanged: `d/d(theta)[M_a*sin(theta)] = 9.0` at `theta = 0`
   and `d/d(theta)[k_a*theta] = 9.0` everywhere.

## Ticks, windows and modes

Mandate correction 2 separates six quantities the prior draft ran together.

| name | symbol | owner | meaning | recorded in |
|---|---|---|---|---|
| scenario tick | `k` | sim | index of a plant step and of the sensor frame sampled at its start, 0 to `T-1` | sensor frame `tick`, sim CSV `tick`, `replay.json.ticks` |
| vehicle cycle index | `n` | vehicle | index of a control cycle, from 0 | actuator frame `veh_tick`; derivable from the record as `tick - tick_base` |
| vehicle logical tick | `expected` | vehicle | the sensor tick cycle `n` is scheduled to consume | control record `tick`, actuator frame `tick` |
| total cycles | `total = warmup + cycles` | vehicle | cycles the loop runs before the horizon | summary `total_cycles` (new) |
| timing warmup cycles | `warmup` | vehicle | `--warmup`, default 5000; cycles before the histograms open | summary `warmup` (new) |
| recorded timing cycles | `cycles` | vehicle | `--cycles`; cycles that feed the histograms | summary `cycles_requested`, and `cycles` for the count actually recorded |
| episode state | `state` | vehicle for its own outcome, sim for the plant's | INIT, ARMED, FLYING, TERMINATED | control record `state`, actuator status byte0, `summary.episode.state` |

`expected` is `tick_base + n` in free-run and the tick of the frame received this
cycle in lockstep. It never depends on `newest_consumed_tick`. Changed from the
prior draft, which defined `current_tick = max(tick_base + n,
newest_consumed_tick)`: mandate correction 6 deletes the `max`, and with it the
name. `current_tick` appears nowhere in this document; `expected` is the one name
for the vehicle's logical tick, used identically in the command protocol, in
`actuator_v1`, in `control_v1` and in the staleness ladder. No value changes; this
is a naming and definition repair.

`--ticks=T` on the sim means T sensor frames, ticks 0 through T-1, and T-1 plant
steps. The frame labelled tick `k` carries `truth_k`, the state at the start of
plant step `k`. That convention holds in both modes; only the position of the
send inside the sim's loop body differs.

The controller is active from the first consumed valid sample or the scenario's
launch transition. `warmup` gates the histograms and the measurement counters and
nothing else. Changed from the prior draft, whose INIT to ARMED transition
required `tick - tick_base >= warmup`; mandate correction 2 deletes that clause,
and the v0.2b plant cannot stay neutral through 5000 cycles anyway.

### The mode field in summary.json

### Two windows and the identities

**Episode window**: cycles `n` in `[0, total)`. Every cycle in it sends one
actuator frame and pushes one control record. Episode counters, ladder counters,
link counters, the settle counter and every terminal decision live here.

**Recorded timing window**: cycles `n` in `[warmup, total)`. The jitter,
execution, served-latency and discard-age histograms and `missed_deadlines` live
here and nowhere else.

Counters are kept twice, once per window, by one struct instantiated twice. The
increment sites are identical and the recorded-window set takes one extra
increment when `n >= warmup`. That is the cost: one predictable branch and one
increment per event. `summary.json` carries `link` for the episode window, which
the reconciliation uses, and `link_recorded` for the recorded window, which
coverage and the gate use.

Each window has one name for its cycle count, used in every identity below and
in every script: `episode_cycles` is `total`, written to `summary.json` as
`total_cycles`, and `recorded_cycles` is `total - warmup`, written as `cycles`.

Episode window:

```
E1  actuator_transmitted + actuator_tx_fail == episode_cycles
E2  fresh + coast + neutral + lost == episode_cycles
E3  received == consumed + discarded_old + discarded_superseded + discarded_nonfinite
              + discarded_skew_excess + discarded_duplicate + discarded_tick_conflict
              + future_expired + future_parked
E4  (sim) generated == intentionally_lost + transmitted
```

Recorded timing window:

```
T1  jitter_us.count == exec_us.count == recorded_cycles
T2  latency_us.count == consumed_recorded
T3  discard_age_us.count == discarded_old_recorded + discarded_superseded_recorded
                          + discarded_other_recorded
T4  received_recorded == consumed_recorded + discarded_old_recorded
                       + discarded_superseded_recorded + discarded_other_recorded
                       + discarded_duplicate_recorded + discarded_tick_conflict_recorded
                       + future_expired_recorded
                       + (future_parked_at_end - future_parked_at_warmup)
```

`latency_us` is the served distribution and nothing else. `discarded_other` is
the per-cycle sum of this cycle's non-finite rejections and this cycle's
excessive-skew discards, which is what the record can carry in one byte; the
run-level counters keep the two apart. The three classes that produce no
discard-age sample are duplicate, tick conflict, and a parked frame that expired,
and they appear only in E3 and T4.

`future_parked` is the future ring's occupancy, at most `skew_max`. It is a
residual term, not a discard: a parked frame has been received and not yet
dispositioned. Changed from both prior area drafts, which stated these identities
with eight terms and no residual. Under the free-run phase pinning below, one
future-dated frame is parked in every steady-state cycle by design, so the run
ends with the ring holding one frame and an identity with no residual fails on
every free-run run. The residual is reported in `<label>.reconcile.json`.

Cross-process reconciliation runs over the overlap of the two windows and never
over the whole run; the windowed uplink identity is under "Wire and transport".

## Lockstep recurrence

Deterministic lane: CI, seed-exact reproduction, replay goldens, future TMR. The
sim owns the clock. No timeout exists in the lane except the resend timer, which
can change whether a run completes and never what it outputs.

### Handshake

The vehicle starts first, binds and connects, and prints one line before RT
setup (grammar under "Wire and transport"):

```
ready mode=lockstep sensor_port=24000 command_port=0 pid=<n> bin=<resolved path> consts=0xe77201ca
```

`scripts/run_scenario.py` waits for it (10 s wall limit, runner exit 6), compares
`consts` against `sim.control_ref.DIGEST` (mismatch is runner exit 7), then starts
the sim. The sim sends first. `tick_base` must be 0; the vehicle asserts it on
the first frame and otherwise terminates PEER_LOST, exit 5. The command socket is
never opened, so nothing outside the scenario can perturb a golden.

### Sim, per tick k from 0

```
A  draws for tick k, in order, one per live stream, unconditionally:
       link.loss.up, link.loss.down
B  env_k  = scenario.environment(k)      -> Environment
   dist_k = scenario.disturbance(k)      -> Disturbance          (tick-indexed, no RNG)
C  obs_k  = sensor.observe(truth_k)      -> Observation          (ideal-v1)
D  frame_k = build(k, obs_k, up_draw, flags, sim_reason_k)
       SAMPLE_VALID clear and theta, omega zero when the up draw said lost
       CMD_PRESENT, opcode, cmd_seq when the scenario issues a command at tick k
       EPISODE_END and sim_reason set per the terminal rules below
       frame seq assigned here, once
E  append frame_k to <label>.inputs.tvcrec, once; send frame_k
F  block on recvfrom until an actuator frame with tick == k arrives; discard anything else
       200 ms socket timeout: resend frame_k byte for byte, up to 25 times (5 s),
       then exit nonzero (runner exit 3). A resend takes no draw and advances no stream.
G  arriving_k = down_draw ? None : frame.delta          (down loss delivers nothing)
H  delayed_k  = delay_fifo.push_pop(arriving_k)         (depth D_flag, prefilled with None)
I  act_{k+1}  = actuator.step(act_k, delayed_k, dt);  applied_k = act_{k+1}.applied
J  if frame_k carried EPISODE_END: write the sim row for k, stop.
       No plant step on a terminal tick.
K  if the actuator frame carried a vehicle terminal reason: write the sim row for k,
       set sim_reason = 4 SIM_VEHICLE_TERMINAL, record the vehicle's reason, stop.
       No further frame is built, because the vehicle has already exited.
L  truth_{k+1} = plant.step(truth_k, applied_k, env_k, dist_k, dt)   -> TruthState
M  sim_reason_{k+1} = terminal_check(truth_{k+1})
N  write the sim golden row for tick k: the sampled state that went on the wire,
       has_sample, applied, cmd_applied_bits
O  if sim_reason_{k+1} is not NONE, or k + 1 == T - 1: mark tick k+1 as the
       EPISODE_END tick, with the precedence below
```

Changed from the prior draft on three points. Step G passes `None` rather than
holding the requested command, so the hold lives in the actuator (above). Step I
uses the single-return actuator signature. Step K is new: the prior draft folded
a vehicle terminal reason into step O and marked tick `k+1` as the EPISODE_END
tick, which builds a frame for a vehicle that has already exited, so the sim
blocks at step F, burns its 25 resends and exits nonzero. S6-blackout, S7-abort
and every run where the ladder or an abort terminates the vehicle first ended
that way. With step K the sim stops at tick `k`, which reproduces the scenario
table below: S6 reason 4 at tick 1020 with fresh/coast/neutral 1000/8/12, S7
reason 3 at tick 1050 with 1051/0/0.

Step J is why the plant never integrates past a loss-of-control point. The
horizon tick `T-1` carries EPISODE_END from the moment it is built, so the mid-run
and horizon paths meet in one place.

**Precedence when more than one condition fires on tick k+1**, highest first:
3 SIM_LOC_NONFINITE, 2 SIM_LOC_ANGLE, 1 SIM_HORIZON. The plant's own outcome
outranks the horizon because the horizon is the absence of any other reason. The
winning code goes into that frame's `sim_reason` field. 4 SIM_VEHICLE_TERMINAL is
not in the precedence list because step K stops the sim before the plant step, so
in lockstep it cannot race a plant outcome. Changed from the prior draft, whose
step N was three disjuncts with no precedence, so a vehicle SENSOR_LOST at `T-2`
could produce either `(4, 4)` or `(1 SIM_HORIZON, 4 SENSOR_LOST)`, and the second
is an integrity failure in lockstep.

### Vehicle, per answered tick

The vehicle's cycle index `n` advances once per newly received sensor tick. With
`tick_base = 0` and no dropped datagrams in lockstep, `n == k` on every cycle, and
a test asserts it.

```
1  block on recv (connected socket, no timeout, type 4 only). Decode and classify
   first, with the same classifier free-run uses, so the datagram is counted in
   received and, on a resend, in discarded_duplicate. Then:
       tick == newest_answered_tick  -> resend the last actuator frame byte for byte,
                                        block again; no cycle, no record, n unchanged
       tick <  newest_answered_tick  -> discard, block again
       tick >  newest_answered_tick + 1 -> the sim never skips: reason 8 INTERNAL, exit 5
2  woke = now_ns()
3  consume: if SAMPLE_VALID and both fields finite -> newest_consumed_tick = tick,
   staleness 0, FRESH_SAMPLE. Otherwise the ladder rung from
   staleness = expected - newest_consumed_tick.
4  if CMD_PRESENT: classify the in-band command, effective_tick = tick + 50, write
   ack_cmd_seq, ack_status and ACK_PRESENT into this cycle's record
5  episode transitions, including a pending command whose effective_tick has arrived
6  controller on a fresh sample, otherwise the ladder rung
7  if EPISODE_END: terminal decision from sim_reason, read off the received frame
   regardless of SAMPLE_VALID
8  send the actuator frame (tick = k, veh_tick = n, both stamps 0, delta, status,
   staleness); newest_answered_tick = k
9  done = now_ns(); push the control record; break if TERMINATED
```

Changed from the prior draft: step 1 classifies before the resend branch fires.
The prior order made a lockstep resend invisible to the classifier, so
`received` never counted it while the sim counted it in `transmitted`, and the
reconciliation identity failed on any resend, which is runner exit 8. The golden
CSVs and `inputs_sha256` are resend-invariant; `transmitted`, `received` and
`discarded_duplicate` are not, and the reconciliation reads all three.

`newest_consumed_tick` and `newest_answered_tick` each carry a has-a-value
boolean. Zero initialisation would make tick 0 "not newer" and hang the
handshake.

### Loss, resends, and clocks in lockstep

No datagram is dropped by design. Uplink loss is a cleared SAMPLE_VALID bit in a
frame that still arrives, so the vehicle always learns the tick and staleness
needs no timeout. Downlink loss is applied on receipt inside the sim at step G. A
resend in either direction retransmits the frame already built, byte for byte,
with its original frame seq: no draw, no stream advance. The `link.loss.up`
stream advances once when tick k is built; the `link.loss.down` stream advances
once per tick at step G.

Every wire frame carries zero timestamps and `inputs.tvcrec`'s header timestamps
are written as 0, so `inputs_sha256` is a pure function of the scenario and the
seed.

### D in lockstep

`--delay-ticks=D_flag` is a whole-tick delay on the arriving command, applied at
step H by a FIFO of depth `D_flag` prefilled with `None`. It is the number of
control periods between the plant sampling `theta_k` and the start of the plant
step that applies the command computed from it.

`D_flag = 0`, which sample drives which step:

```
obs_0 -> vehicle -> delta_0 -> step 0 applies delta_0   (truth_0 -> truth_1)
obs_1 -> vehicle -> delta_1 -> step 1 applies delta_1   (truth_1 -> truth_2)
obs_2 -> vehicle -> delta_2 -> step 2 applies delta_2
```

`D_flag = 1`:

```
obs_0 -> vehicle -> delta_0 -> FIFO;  step 0 applies 0.0   (the actuator's initial state)
obs_1 -> vehicle -> delta_1 -> FIFO;  step 1 applies delta_0
obs_2 -> vehicle -> delta_2 -> FIFO;  step 2 applies delta_1
```

`D_eff = 0` is not physically realizable in free-run. It exists because the
known-answer corpus and the goldens are defined there and because it is the
cleanest deterministic reference. `D_eff = 1` reproduces the free-run design
point inside the deterministic lane.

## Free-run recurrence

Qualified timing lane. Sim and vehicle each run their own 500 Hz schedule from
`origin + n * period_ns` on CLOCK_MONOTONIC. The vehicle's cycle contains no
blocking call under any flag value.

### Sim startup, and why the phase is pinned

Before the loop:

```
t_prologue = now_ns()
sendto(prologue frame, tick 0, truth_0)
sim_origin = t_prologue
```

The prologue gives the vehicle a frame to set its origin from. `sim_origin` is
the prologue send, so the tick-0 body runs with no sleep and its send lands
immediately after the prologue. Changed from the prior draft, which left
`sim_origin` unrelated to the prologue send: with `delta = sim_origin -
t_prologue_send`, a `delta` at or below `phase_us` gives `D_transport = 1`, a
`delta` above `phase_us` and at or below `phase_us + period_ns` gives
`D_transport = 0`, and a larger `delta` leaves the vehicle permanently stale by
`ceil((delta - phase_us) / period_ns)` ticks and parked on the coast rung for the
whole run. Copying the harness idiom `origin = now_ns() + 10 * kNsPerSec / 1000`
(`src/main.cpp:361`) would pin staleness at 5 for every cycle of every run
(probe: `python3 probe.py phase`). Mandate correction 6 requires the relationship
among lockstep `D = 0`, lockstep `D = 1` and free-run scheduling to be
unambiguous, and this is what makes it so.

The prologue is frame 0 and takes the up stream's draw 0. Its outcome is
overridden to send, counted in `forced_transmit`, because the vehicle's origin
acquisition has no other way to start. Body tick `k` then takes draw `k+1` for the
frame labelled `k+1`, so the up stream's draw index equals the frame index and the
stream's position stays a pure function of that index. Changed from the prior
draft, in which the prologue was built and transmitted without a draw, which
broke `generated == intentionally_lost + transmitted` by one and put an unstated
exemption under the public 30% claim. The rejected alternative: let the prologue
take draw 0 with no override, end the vehicle's 5 s origin wait in reason
5 PEER_LOST when it is lost, and have `scripts/run_scenario.py` retry the run
once. That trades a deterministic start for a retry path and a `"prologue_lost"`
key nobody reads.

### Sim, per tick k, in the mandate's normative order

The sim sleeps to `sim_origin + k * period_ns` at the top of the body. The body's
send carries the frame labelled `k+1`: tick `k`'s work integrates
`truth_k -> truth_{k+1}` and transmits what that produced.

```
 1 read available actuator frames
      bounded nonblocking drain, at most 8 datagrams; malformed datagrams counted and dropped
 2 select the requested command
      one down draw per accepted datagram, in receive order, unconditionally;
      drop when u < p_down; among survivors take the largest tick, count the rest
      in actuator_superseded; no survivor -> arriving_k = None
      read the survivor's state, reason and staleness for the terminal protocol
 3 advance actuator state
      delayed_k = delay_fifo.push_pop(arriving_k)
      act_{k+1} = actuator.step(act_k, delayed_k, dt)          -> ActuatorState
 4 determine applied gimbal
      applied_k = act_{k+1}.applied                            -> rad, held across dt
 5 compute environment and disturbance
      env_k  = scenario.environment(k)                         -> Environment
      dist_k = scenario.disturbance(k)                         -> Disturbance
      no RNG draw: every v0.2b scenario element is deterministic and tick-indexed
 6 integrate the plant
      truth_{k+1} = plant.step(truth_k, applied_k, env_k, dist_k, dt)   -> TruthState
 7 sample truth
      the state the sensor observes for the frame labelled k+1
 8 generate the observation
      obs_{k+1} = sensor.observe(truth_{k+1})                  -> Observation, ideal-v1
 9 apply sensor-link loss
      one up draw, unconditional, before any decision that could skip the send
      lost -> no send; the built frame still consumes its seq, so the wire shows a gap
10 send
      t_send_ns = now_ns() immediately before sendto, then sendto
```

Changed from the prior draft on three points: step 4 reads the new actuator
state rather than recomputing from the old one; step 5 no longer takes scenario
and noise draws, because mandate correction 5 removes sensor noise and no v0.2b
scenario element is stochastic; and step 2's superseded survivors are counted.

The `link.loss.down` stream draws once per received actuator datagram in free-run
and once per tick in lockstep. The count of received datagrams per sim tick
depends on timing, so the free-run `down` stream's position is not a function of
the tick index. That is why seed reproduction is claimed only in lockstep.

### Vehicle: origin acquisition

One bounded blocking `recv` before the loop, `SO_RCVTIMEO` 5 s, outside the
control cycle. Timeout is reason 5 PEER_LOST, exit 5. On success:

```
tick_base   = first_frame.tick
origin      = first_frame_arrival_ns + phase_offset_ns      // --phase-us, default 400
deadline(n) = origin + n * period_ns
expected(n) = tick_base + n
```

The first frame is decoded and placed in a one-slot carry buffer that cycle 0
classifies before it drains the socket. It is cycle zero's candidate observation
and is never discarded during initialisation. Changed from the prior draft, which
consumed the frame in the origin wait and threw it away; mandate correction 6
requires it to be retained.

`staleness = expected - newest_consumed_tick` is non-negative by construction,
because the classifier below never consumes a frame with `tick > expected`, so it
needs no clamp.

### Vehicle, per cycle n

```
 1 clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, deadline(n)), retry on EINTR
      the same call as src/main.cpp:368-373
 2 woke = now_ns()
 3 one recvmmsg(fd, msgs, 8, MSG_DONTWAIT, NULL); rx = now_ns()
      on cycle 0 the carry buffer is classified first, then the batch
      hitting the bound of 8 sets RX_OVER_BOUND; leftovers stay queued for the next cycle
 4 re-index the future ring against this cycle's expected, then classify every
   datagram (table below)
4b terminal read: among this cycle's well-framed datagrams whose tick is at most
   expected, take the largest tick; if EPISODE_END is set, latch (sim_reason, that
   tick) for step 7. The latch is independent of SAMPLE_VALID and of field
   finiteness. A latched terminal reason is never cleared by a later datagram. A
   parked future frame is never latched; it is read only when re-classification
   brings its tick to expected.
 5 consume: among this cycle's class-6 candidates take the largest tick; if
   SAMPLE_VALID and both fields finite, consume it (newest_consumed_tick = tick,
   staleness 0, FRESH_SAMPLE). Every other class-6 candidate is superseded and
   contributes one discard-age sample.
 6 pop at most one command from the 64-slot drain-to-control ring, classify it,
   write ack_cmd_seq, ack_status and ACK_PRESENT into this cycle's record
 7 episode transitions, in order: sim terminal reason from the latched EPISODE_END
   read of step 4b; a pending command whose effective_tick <= expected; per-cycle
   terminal checks (DIVERGED, SENSOR_LOST, PEER_LOST); --auto-arm INIT to ARMED to
   FLYING on the first consumed valid sample; the horizon check at n == total - 1
 8 controller on a fresh sample, otherwise the ladder rung
 9 one send(fd, frame, len, MSG_DONTWAIT); tx = now_ns()
      EAGAIN clears TX_OK and counts actuator_tx_fail; ECONNREFUSED counts peer_refused
10 done = now_ns(); push the control record (every cycle, warmup included)
11 if n >= warmup: stats.record(woke - deadline(n), naive_jitter, done - woke);
   note_missed() when done > deadline(n) + period_ns; the served and discard-age
   samples from this cycle
```

Step 4b is new. Changed from the prior draft, whose free-run step 5 read the
terminal reason only off a *consumed* frame, so a terminal frame whose sample was
invalid or non-finite was discarded with its reason, all twelve copies of it, and
the vehicle reported NOT_SETTLED against the sim's terminal code. Splitting the
terminal read from the consume test is what makes free-run read the reason the
same way lockstep step 7 does. With the sim's terminal check running after every
plant step at `|theta| > 0.30`, `sim_reason` 3 SIM_LOC_NONFINITE is not reachable
from a finite state under the v0.2b plant; the split exists so the `(3, 7)` row
of the agreement table cannot fire spuriously and so the reason never depends on
the sample being usable. For `sim_reason` 2 the sample is finite, valid, consumed
and mapped correctly either way.

Step 11 keeps the shape of `src/main.cpp:420-426`, including the `naive_jitter`
series, so L7 and L8 are comparable on the same two distributions.

### Datagram classification

`expected = tick_base + n`. Classes are evaluated in this order, one pass per
datagram. A `last_rx_payload` buffer sized by the `sensor_v1` payload, 44 bytes,
holds the newest received frame's payload for the duplicate test, with
`static_assert(sizeof(last_rx_payload_) == kSensorV1PayloadBytes);` beside it and
the Python side reading `PAYLOAD_SIZES[4]` rather than a literal. Changed from
the prior draft's 40-byte buffer, which was a pre-correction-7 constant and left
`sim_reason` outside the comparison. A conforming sim cannot produce a same-tick
pair differing only in `sim_reason`, because EPISODE_END lives in `flags` at
offset 32 inside the compared range and `sim_reason` is nonzero exactly when
EPISODE_END is set, so the four uncompared bytes cost nothing against a
conforming peer and cost the whole point of the class-4 tripwire against one that
is not.

| # | class | test | action | counter |
|---|---|---|---|---|
| 1 | malformed | sync, version, type, length or CRC check fails | discard | `link.bad_sync`, `bad_version`, `bad_type`, `bad_length`, `bad_crc` |
| 2 | non-finite | SAMPLE_VALID set and `theta` or `omega` is NaN or infinite | discard the sample, never consumed, sets NONFINITE_REJECTED, contributes one discard-age sample; the frame's EPISODE_END and `sim_reason` are still read by step 4b | `discarded_nonfinite` |
| 3 | duplicate | `tick == newest_received_tick` and payload equals `last_rx_payload` | discard, no sample | `discarded_duplicate` |
| 4 | identity conflict | `tick == newest_received_tick` and payload differs | discard, no sample, link integrity event | `discarded_tick_conflict` |
| 5 | old | `tick <= newest_consumed_tick` | discard, one discard-age sample | `discarded_old` |
| 6 | current or catch-up | `newest_consumed_tick < tick <= expected` | consumption candidate; losers are superseded, one discard-age sample each | `consumed`, `discarded_superseded` |
| 7 | future within skew | `expected < tick <= expected + skew_max` | park in the future ring at index `tick - expected - 1`; not consumed, no sample yet | `future_parked` |
| 8 | excessive forward skew | `tick > expected + skew_max` | discard, one discard-age sample, link integrity event | `discarded_skew_excess` |

A class-6 frame with SAMPLE_VALID clear is received and not consumed: it advances
`newest_received_tick` and tells the vehicle the tick exists, and it does not
reset staleness. In free-run uplink loss is a non-send rather than a cleared bit,
so this branch fires only on a sim-side sensor fault; it costs one bit test and
it lets lockstep and free-run share one classifier.

`rx_count` in the record counts the datagrams classified this cycle, including
the carry buffer on cycle 0, so the decoder asserts `rx_count <= 9`. The
origin-wait frame is therefore counted exactly once, in cycle 0.

### The future ring

The future buffer is a ring of `skew_max + 1 = 5` frames indexed by
`tick - expected - 1`, re-indexed against the new `expected` before each cycle's
drain. A parked frame becomes class 6 when `expected` reaches its tick. A frame
that ages past `expected + skew_max` is dropped and counted `future_expired`. A
second frame arriving for an occupied index carries the same tick, so it takes
the duplicate test exactly as class 3 and class 4 do: `discarded_duplicate` when
the payload matches, `discarded_tick_conflict` when it does not.

Changed from the prior draft's one-slot buffer, which had no rule for the loser
when two frames arrived for different future ticks, and which was undersized for
the design's own phasing. A parked frame never advances command application and
never advances episode state, which is mandate correction 6's requirement, made
structural rather than a rule someone has to remember.

`skew_max = 4` ticks, 8 ms, flag `--skew-max-ticks=4`, parse-time error above 64.
Sizing: sim and vehicle run the same `period_ns` arithmetic from independent
origins on one CLOCK_MONOTONIC, so there is no systematic drift. Four ticks is
8 ms: 4x the period, 20x the 400 us phase offset and about 485x the observed
p99.9 wakeup jitter of 16.5 us (`docs/results.md:433`). Below 4 the class would
fire on ordinary CPython scheduling noise; above 4 the vehicle would consume a
sample whose age it cannot bound.

One parked future frame per cycle is the design point, not a transient: with
`sim_origin` pinned to the prologue send, `D_transport = 1` and every steady-state
cycle receives the frame for `expected + 1` and consumes the one parked last
cycle. `future_parked` is a cadence counter, and `future_expired` is the anomaly
counter. Changed from the prior draft, whose sizing rationale called a future
frame a transient.

Above the bound the datagram is discarded and counted. `discarded_skew_excess`
and `discarded_tick_conflict` never terminate the episode: a stray datagram must
not end a campaign row. A nonzero total at the end of the run is exit 6, link
integrity failed, alongside the malformed counters, because the vehicle cannot
bound the age of a sample that far ahead. Changed from the prior draft's
justification, "there is no legitimate source": a vehicle stall is a legitimate
source, and `missed_deadlines` already records it.

### Missed deadlines and catch-up

`clock_nanosleep(TIMER_ABSTIME)` against `origin + n * period_ns` returns
immediately when `deadline(n)` is already past, so the vehicle runs back to back
until it catches up, and `missed_deadlines` counts it.

A missed deadline leaves the vehicle behind its own schedule, so queued frames
arrive future-dated relative to `expected` rather than as class-6 catch-up. A
stall shorter than `skew_max` periods is absorbed by the future ring with
staleness 0. A stall of `skew_max` periods or longer produces
`discarded_skew_excess` and ends the run's publishability, which is the intended
behaviour. Changed from the prior draft, whose catch-up paragraph claimed the
queued frames classify as class 6; `expected` does not advance during a stall, so
they cannot.

### D reconciliation

`--delay-ticks=D_flag` is an explicit whole-tick delay the sim adds to the
arriving command. The schedule adds its own transport delay. The effective loop
delay is the sum:

```
D_eff = D_transport + D_flag
```

| mode | `--delay-ticks` | `D_transport` | `D_eff` | why |
|---|---|---|---|---|
| lockstep | 0 | 0 | 0 | the sim blocks for the answer to tick k before stepping k |
| lockstep | 1 | 0 | 1 | reproduces the free-run design point deterministically |
| lockstep | D | 0 | D | delay-margin sweeps |
| freerun | 0 (default, L8) | 1 | 1 | `sim_origin == t_prologue_send` and `0 < phase_us < period_ns`; the vehicle wakes `phase_us` after the sim's tick boundary and answers within that tick, and the sim's next read is at the following boundary |
| freerun | D | 1 | 1 + D | |

The boundaries, from the probe: a sim origin more than `phase_us` past the
prologue send makes `D_transport = 0`; a sim origin more than
`phase_us + period_ns` past it leaves the vehicle permanently stale by
`ceil((delta - phase_us) / period_ns)` ticks (probe: `python3 probe.py phase`).
The delay-margin table under "Controller" is indexed by `D_eff`, not by the flag.

## Terminal-state protocol

### sim_reason

`EPISODE_END` carries `sim_reason`, an authoritative u32 the simulator owns, at
`sensor_v1` offset 40. It is present on every sensor frame, meaningful only when
EPISODE_END is set, and 0 otherwise.

| code | name | meaning | on the wire |
|---|---|---|---|
| 0 | SIM_NONE | not terminal | yes |
| 1 | SIM_HORIZON | the scenario's scheduled last tick was reached | yes |
| 2 | SIM_LOC_ANGLE | the true state exceeded the loss-of-control angle after a plant step | yes |
| 3 | SIM_LOC_NONFINITE | the true state went non-finite after a plant step | yes |
| 4 | SIM_VEHICLE_TERMINAL | the vehicle's actuator frame carried a terminal reason; the sim records it so the run's last statement is authoritative about why it stopped | yes in free-run; `replay.json` only in lockstep, where step K stops the sim before another frame is built |
| 5 | reserved | | no |
| 6 | SIM_PEER_LOST | the sim gave up on the vehicle (lockstep resend budget exhausted, or free-run grace expired) | `replay.json` only |

This is a separate enum, not a shared table with the vehicle's `reason`. Changed
from the prior draft's protocol section, which folded the sim's outcome into the
vehicle's nine-value table and added a code 9 SIM_HORIZON. SIM_VEHICLE_TERMINAL
has no meaning in the vehicle's own table, so a shared table cannot express it.
The cost is that the two enums overlap numerically: 1 and 2 mean different things
in `sim_reason` and in `reason`. That is why the agreement table below is keyed by
name and both fields are strictly typed at the decode boundary.

The vehicle's nine-code reason table is unchanged: 0 NONE, 1 STABILIZED,
2 DIVERGED, 3 GROUND_ABORT, 4 SENSOR_LOST, 5 PEER_LOST, 6 SIGNAL, 7 NOT_SETTLED,
8 INTERNAL.

### Mapping, on the EPISODE_END cycle

| `sim_reason` | vehicle reason | note |
|---|---|---|
| 1 SIM_HORIZON | 1 STABILIZED if the settle window held, else 7 NOT_SETTLED | the horizon is the vehicle's own evaluation point |
| 2 SIM_LOC_ANGLE | 2 DIVERGED | assigned without reading `theta` |
| 3 SIM_LOC_NONFINITE | 2 DIVERGED | one vehicle-side code for the class |
| 4 SIM_VEHICLE_TERMINAL | whatever the vehicle already assigned itself | the echo changes nothing |
| 0 SIM_NONE with EPISODE_END set | 8 INTERNAL | a terminator with no reason is a protocol bug |

This is how a true loss of control reaches the vehicle on a cycle whose
observation was invalidated by link loss. The frame arrives with SAMPLE_VALID
clear, `theta` and `omega` zero, EPISODE_END set and `sim_reason = 2`; the vehicle
assigns DIVERGED from the reason, not from the sample. Under the prior draft the
vehicle ran its horizon evaluation on a stale sample and reported NOT_SETTLED,
which is the failure mandate correction 7 names.

### Free-run terminal handshake

Lockstep has no grace phase. The sim blocks for the answer and resends up to 25
times; that path already covers a kernel drop and takes no draws.

Free-run, one design:

1. When the sim's tick-k body decides the episode is over, it builds the terminal
   sensor frame (EPISODE_END set, `sim_reason` set, the observation for tick k+1
   as normal) and enters the grace phase. It performs no further plant step.
2. The sim keeps ticking on its 500 Hz schedule for `R = 12` ticks, transmitting
   the same byte-identical terminal frame on each, each taking that tick's `up`
   draw. Terminal copies are subject to the loss model like any other frame: no
   frame inside the episode is exempt, so the unconditional draw discipline stays
   literally unconditional and the public 30% claim needs no footnote. The
   prologue takes its draw and overrides the outcome to send, and its override is
   the only one in a free-run run. `--terminal-copies=12`, parse-time bounds 1
   through 64. The frame is appended to `inputs.tvcrec` once, at the tick it was
   built.
3. The vehicle terminates on the first copy it consumes: it assigns its reason
   from the mapping, sends its terminal actuator frame, then runs a terminal loop
   of `R = 12` cycles at its normal cadence, re-sending that identical frame on
   each, and exits. The terminal loop sleeps and sends; it does not receive, does
   not run the controller, pushes no records and feeds no histogram. Later sensor
   copies queue and die with the socket.
4. The sim stops as soon as it accepts an actuator frame whose status byte0 says
   TERMINATED, or when the grace budget expires: `R` terminal ticks plus
   `G_sim = 10` further ticks, 20 ms. On expiry with no terminal answer the sim
   writes `"vehicle_reason": null` and `"terminal_handshake": "unanswered"` into
   `replay.json`, sets its own `sim_reason` as the outcome, and exits nonzero
   (runner exit 3).
5. Counters: `summary.episode.terminal_copies_sent` and
   `replay.json.terminal_copies_sent`. Terminal copies are outside
   `actuator_transmitted` and outside the sim's `generated`, so identities E1 and
   E4 are unaffected.

Sizing. At `p_up = p_down = 0.30`, P(all 12 copies lost in one direction) =
5.31e-7 (probe: `python3 -c "print(0.3**12)"`), and P(a terminal handshake goes
unanswered) = 1.06e-6 per free-run episode (probe:
`python3 -c "print(1-(1-0.3**12)**2)"`). At `R = 3` it is 0.053 per episode,
which would make a false integrity failure a routine event in a free-run test
suite; `R = 5` is 0.0049. `R = 12` costs 24 ms of sim time, up to 24 ms of
vehicle time, and 24 datagrams per episode. The free-run runs that exist are
capability 6's functional tests and capability 9's 150,000-cycle L8 episode.
Changed from the prior draft, which priced the count against the 400-run release
campaign: that campaign runs in-process through `sim.run_headless` in lockstep,
which has no grace phase and never reaches this path, and its own arithmetic was
off by about twenty times. The residual 1.06e-6 goes into `docs/results.md` as
the handshake's stated failure probability rather than being left implicit.

### Both outcomes recorded, and the comparison

`summary.json`'s `episode` block carries `reason`, `reason_name`, `sim_reason` and
`sim_reason_name`; the vehicle knows both because `sim_reason` arrived on the
EPISODE_END frame. `replay.json` carries `sim_reason`, `sim_reason_name`,
`vehicle_reason` and `vehicle_reason_name`. The runner compares all four, which
also covers the case where the EPISODE_END frame never reached the vehicle.

An unexpected pairing is **runner exit 8**, named in the run result:

```
integrity: sim_reason=SIM_LOC_ANGLE@7412 vehicle_reason=NOT_SETTLED@9999 (unexpected)
```

and `"integrity": {"terminal_agreement": false, "sim_reason": ...,
"vehicle_reason": ...}` in the runner's result JSON. `sweep.row_problem` excludes
any row whose `episode.terminal_agreement` is false, with that reason.

Expected pairings, table of record, mirrored in `sim/episode.py` and
`src/episode.hpp` as `TERMINAL_AGREEMENT` keyed by
`(mode, sim_reason, vehicle_reason)`, with a unit test asserting the two tables
are equal:

| `sim_reason` | vehicle reason | mode | expected | why |
|---|---|---|---|---|
| 1 SIM_HORIZON | 1 STABILIZED | both | yes | the settle window held |
| 1 SIM_HORIZON | 7 NOT_SETTLED | both | yes | reached the horizon without settling; S4-open ends this way by design |
| 2 SIM_LOC_ANGLE | 2 DIVERGED | both | yes | |
| 3 SIM_LOC_NONFINITE | 2 DIVERGED | both | yes | |

The two expected disagreements are the two the mandate asks about.
`SIM_HORIZON` with `NOT_SETTLED`: the sim's horizon says when the episode ended
and the vehicle's verdict says how well it flew, so they answer different
questions. In free-run, `SIM_VEHICLE_TERMINAL` paired with the vehicle's own 1 or
7: the L8 sweep gives the sim a `--ticks` above `warmup + cycles`, so the
vehicle's horizon always fires first.

## Staleness ladder and episode machine

```
staleness = expected - newest_consumed_tick
```

Checked once per cycle, after the drain and before the controller. Before the
first consumed sample, staleness is `n + 1`, saturating, and `sensor_tick` is
`0xFFFFFFFFFFFFFFFF`. With the first frame retained as cycle zero's candidate,
the ordinary case is staleness 0 at cycle 0. Changed from the prior draft, whose
protocol section wrote `tick + 1` while its execution section wrote
`expected - tick_base + 1`; the two differ by `tick_base`, which is nonzero in
free-run, and `n + 1` is the form that matches both and cannot overflow the u32
from a large `tick_base`.

Fresh is an event, not a band: a valid, finite sample with
`tick > newest_consumed_tick` was consumed this cycle. The PID runs exactly once
per new sample.

| staleness | rung | command | controller state |
|---|---|---|---|
| 0 | fresh | PID output | updated |
| 1 through 8 | coast | `last_delta` | frozen |
| 9 through 20 | neutral | 0.0 | frozen |
| above 20 | lost | 0.0, reason 4 SENSOR_LOST, one final frame | |

`K_coast = 8` (16 ms) and `K_neutral = 20` (40 ms) come from the physics probe
and are unchanged. The vehicle emits one actuator frame per cycle regardless of
rung, which is the release predicate's cadence clause and is checked over the
episode window.

The rung is a function of staleness alone and is counted on every vehicle cycle,
including cycles in INIT and ARMED where the commanded gimbal is 0.0 because the
controller is not driving. That counting rule is what makes E2 close.

Ladder usage over 200 episodes at `p = 0.30`, `D_eff = 1` (probe:
`python3 probe.py ladder 200`): fresh 1,398,826 + coast 601,149 + neutral 25 +
lost 0 = 2,000,000, the episode-tick total, and the gimbal was saturated on
47,867 ticks (2.39%). Changed from the prior draft's coast 601,069, which was low
by 80 because the probe incremented the coast and neutral counts only inside the
`state == FLYING` branch while the saturation percentage used the full
2,000,000 denominator. The neutral rung is not dead code in the headline run.

Supporting outage measurement (probe: `python3 probe.py outage 2000`): the
longest uplink outage over 2000 seeds at `p = 0.30`, `D_eff = 1` is p50 7, p95 9,
max 14 ticks, which leaves 6 ticks of headroom to the 20-tick SENSOR_LOST rung.
The prior draft reported a max of 13 over the same seed count; treat 14 as the
number to design against and let capability 3b re-measure it from the shipped
sim.

### States and transitions

| value | state | meaning |
|---|---|---|
| 0 | INIT | bound, no sample consumed |
| 1 | ARMED | a sample has been consumed; the controller is not driving |
| 2 | FLYING | the controller or the ladder drives the actuator |
| 3 | TERMINATED | `reason != 0`, terminal frames emitted, loop exits |

| from | to | trigger |
|---|---|---|
| INIT | ARMED | `--auto-arm` and a consumed valid sample; or a legal ARM at its `effective_tick` |
| ARMED | FLYING | `--auto-arm`, same cycle as ARM; or a legal LAUNCH at its `effective_tick` |
| INIT, ARMED, FLYING | TERMINATED | reasons 2 through 8, evaluated every cycle |
| any | TERMINATED | reason 1 or 7, evaluated only at the horizon |

There is no warmup condition on either transition. Changed from the prior draft,
whose INIT to ARMED trigger read `--auto-arm` and `tick - tick_base >= warmup`
and a fresh sample; mandate correction 2 deletes the warmup clause, and the
v0.2b plant diverges long before cycle 5000.

Without `--auto-arm` the vehicle stays in INIT and emits `cmd = 0.0` every cycle,
which is what S4-open uses to pin the open-loop plant recurrence. The
scenario-defined launch transition is the in-band LAUNCH command in lockstep and
a ground LAUNCH in free-run. Mid-run terminal reasons still fire in INIT: an
open-loop run that crosses the loss-of-control angle terminates.

There is no DISARM and no path out of TERMINATED. Transitions run before the
controller on the same cycle.

### The horizon and the settle window

Reason 1 is assigned only at the horizon: the EPISODE_END cycle in lockstep,
`n == total - 1` in free-run. The vehicle keeps a running count of consecutive
cycles whose most recent consumed sample satisfies both

```
|theta| <= THETA_SETTLE    and    |omega| <= OMEGA_SETTLE
```

with `THETA_SETTLE = 0.02 rad` and `OMEGA_SETTLE = 0.02 rad/s`. As coded, per
cycle, after the sensor drain and before the controller:

```
if |held.theta| <= THETA_SETTLE and |held.omega| <= OMEGA_SETTLE:
    settle_count += 1
else:
    settle_count = 0
```

`held` is the most recently consumed observation. A stale cycle holds the count
rather than resetting it, because the last consumed sample is still the vehicle's
best statement about the band. Reason 1 when the count is at least 1000 at the
horizon, else reason 7. No per-cycle settle termination and no early exit.
Changed from the prior draft, whose vehicle-side window tested `|theta|` alone;
mandate correction 13 requires both, and the vehicle's own verdict must use the
same definition as the offline release predicate.

The settle window sits inside the episode window, and `--cycles` below 1000 is a
usage error in free-run so it always fits. At the L8 configuration
(`--warmup 5000 --cycles 300000`) the window is cycles 304000 through 304999,
inside the recorded timing window as well.

### How the offline predicate and the vehicle result can differ

The offline release predicate reads the simulator's truth trajectory, every tick.
The vehicle reads the observations it consumed, which under loss is a subsampled
and delayed view of the same trajectory. Two disagreements are possible in
principle:

1. **Vehicle says stabilized, truth says not.** The truth leaves the band during
   an uplink gap and returns before the next fresh sample.
2. **Vehicle says not settled, truth says settled.** The last consumed sample sat
   outside the band and the truth came back inside before the next fresh sample.

The gap is at most 20 ticks, the neutral rung's limit, because the settle counter
holds on every stale cycle and only staleness 21 ends the episode. An excursion
invisible to the vehicle has to leave the band and return inside 40 ms, which
needs `|omega| >= 0.5 rad/s`: 8,000x the largest window rate observed at
`p = 0.30` and twice the rate a band-filling oscillation at the closed-loop
bandwidth would produce. The count also survives consecutive gaps, so this is a
bound on one gap and not on the run, which is why the offline predicate on
simulator truth and not this argument is authoritative for the release gate.
Changed from the prior draft, which used the 8-tick coast limit and reported
20,000x and 5x: dropping to the neutral rung does not end the gap.

Measured: 0 disagreements over 1,245 runs that reached their horizon, across `p`
in {0, 0.30, 0.50, 0.70} and `D_eff` in {0, 1} (probe: the `predicate` command's
last column).

The reconciliation rule: **the offline predicate on simulator truth is
authoritative for the release gate**, because it is the only view that sees every
tick. The vehicle's reason is its own view of the same window and is recorded
beside the simulator's outcome. `scripts/run_scenario.py` compares them and
records `settle_agreement`; a disagreement is an integrity finding that goes in
the run result and stops the campaign, on the strength of the 0-in-1,245
measurement.

## Command protocol

Free-run only. In lockstep the command socket is never opened and scenario
commands ride in the sensor frame: flags bit2 CMD_PRESENT, opcode in flags bits
8-15, `cmd_seq` in the sensor payload, `effective_tick = tick + 50` as a rule with
no wire field. One classifier on the control thread serves both paths.

`expected` is the vehicle's logical tick, defined once under "Ticks, windows and
modes", and it is the only tick this section compares against. Changed from the
prior draft, which was written entirely in terms of `current_tick`, a symbol
mandate correction 6 deleted; no value changes.

**`link_sim` impairs the sensor and actuator directions only.** Ground command
and ack datagrams cross the same loopback, take no RNG draw, and are never
dropped by the simulator. The 30% loss claim says nothing about command delivery.
There is no ground-command fault model in v0.2b, and the public wording must not
imply one. Changed from the prior draft, which computed P(no copy delivered) and
P(no ack ever seen) at `p = 0.30` each way; that calculation is removed, because
mandate correction 10. The station's retransmit (10 sends at 20 ms) stays,
justified by the at-least-once uplink contract and by kernel-buffer drops.

### State

One pending non-abort command slot, plus
`last_accepted = {cmd_seq, opcode, effective_tick}`, unset until the first
acceptance, plus one deferred-ack slot.

```
gap    = (cmd_seq - last_accepted.cmd_seq) mod 2^32
newer  = last_accepted unset or (1 <= gap < 2^31)
same   = last_accepted set and cmd_seq == last_accepted.cmd_seq
```

### Status table, ack_v1 offset 12, u16

| code | name | meaning | applied_tick |
|---|---|---|---|
| 0 | QUEUED | accepted into the pending slot, `effective_tick > expected` | 0 |
| 1 | APPLIED | `effective_tick == expected`, took effect this cycle | the tick |
| 2 | APPLIED_LATE | `effective_tick < expected`, took effect this cycle | the tick |
| 3 | DUPLICATE | `same` and identical opcode and effective_tick; no state change | 0 |
| 4 | REJECTED_PENDING | a non-abort command arrived while a non-abort command is pending, or an ABORT arrived while an ABORT is pending | 0 |
| 5 | REJECTED_STATE | the opcode is illegal in the episode state at the effective tick | 0 |
| 6 | REJECTED_IDENTITY | `same` cmd_seq with a different opcode or effective_tick | 0 |
| 7 | REJECTED_OPCODE | opcode not in {1, 2, 3} | 0 |
| 8 | REJECTED_STALE | not `newer` and not `same` | 0 |
| 9 | PREEMPTED | the pending non-abort command an ABORT displaced | 0 |
| 10 | REJECTED_OVERFLOW | the drain-to-control ring was full; the drain emits this one | 0 |

Changed from the prior draft: SUPERSEDED (4) is replaced by REJECTED_PENDING and
PREEMPTED, and REJECTED_STALE, REJECTED_IDENTITY, REJECTED_OPCODE and
REJECTED_OVERFLOW are new, because mandate correction 10. The prior six-value
table collapsed "retransmit of a command I already accepted" and "a command whose
sequence went backwards" into one DUPLICATE code, and had no result at all for a
full ring.

### Classification, in order

At most one command is popped from the drain-to-control ring per cycle.

1. `opcode not in {1,2,3}` -> REJECTED_OPCODE.
2. `same` and identical opcode and effective_tick -> DUPLICATE. No state change,
   including when the matching command is still pending.
3. `same` and any field differs -> REJECTED_IDENTITY. No state change.
4. not `newer` -> REJECTED_STALE.
5. a. `newer`, opcode is ABORT, and a non-abort command is pending: the ABORT is
   accepted, the pending non-abort is displaced and owed a PREEMPTED ack,
   `last_accepted` advances.
   b. `newer`, opcode is ABORT, and an ABORT is pending: REJECTED_PENDING.
   `last_accepted` does not advance, so a retransmit of the rejected ABORT is
   rejected the same way.
6. `newer`, opcode is not ABORT, and a non-abort command is pending ->
   REJECTED_PENDING. `last_accepted` does not advance.
7. `newer`, accepted: `last_accepted` advances now. If `effective_tick <=
   expected` the command is evaluated for legality and applied this cycle,
   APPLIED or APPLIED_LATE or REJECTED_STATE. Otherwise it enters the pending
   slot, QUEUED.

Rule 5b is new. Changed from the prior draft, whose rule 5 accepted any ABORT and
overwrote the pending slot, so an ABORT arriving while an ABORT was pending
displaced it with no ack. That is reachable with three operator keys: ARM with a
future `effective_tick` (QUEUED), ABORT with a future `effective_tick`
(PREEMPTED plus QUEUED), second ABORT. Rule 5b does not break retries, because
rule 2 still precedes it: a retransmit of the pending ABORT with identical
`cmd_seq`, opcode and `effective_tick` is DUPLICATE, and 5b catches only a
genuinely new ABORT. The rejected alternative: accept the second ABORT and owe the
displaced one a PREEMPTED ack, which also keeps the deferred slot at one entry
and adds a second preemption path for a case three operator keys never produce.

A pending command fires on the first cycle whose `expected` reaches its
`effective_tick`. **Legality is evaluated at the effective tick, never at
arrival**, because the episode state at arrival is not the state the command acts
on: `--auto-arm` and any terminal transition can move it in between. A queued
command therefore produces two acks on two different cycles, QUEUED then APPLIED
or REJECTED_STATE.

The known limitation: with one pending slot, a station cannot pipeline ARM and
LAUNCH. The second gets REJECTED_PENDING and must be re-sent after the first
applies. That is the cost of correction 10's single-slot rule and it is
acceptable for a release whose only commands are three operator keys.

### Legality by state, evaluated at the effective tick

| opcode | INIT | ARMED | FLYING | TERMINATED |
|---|---|---|---|---|
| 1 ARM | legal | REJECTED_STATE | REJECTED_STATE | unreachable |
| 2 LAUNCH | REJECTED_STATE | legal | REJECTED_STATE | unreachable |
| 3 ABORT | REJECTED_STATE | legal | legal | unreachable |

TERMINATED is unreachable because the loop exits on the cycle that sets it.

### One ack per record, and the deferred slot

The record carries one ack. The only case that owes two acks in one cycle is an
ABORT preempting a pending non-abort command. The ABORT's ack rides this cycle's
record; the PREEMPTED ack for the displaced `cmd_seq` rides the next cycle's
record, and while a deferred ack is outstanding the classifier does not pop from
the drain-to-control ring.

The deferred slot holds at most one entry by construction: only a pending
non-abort command can be preempted, after preemption the pending slot holds the
ABORT, and rule 5b refuses an ABORT over a pending ABORT. The cost is at most one
cycle, 2 ms, of command latency in exactly that case.
`tests/cpp/episode_tests.cpp` drives ABORT-over-pending and asserts two acks on
two consecutive records with the right `cmd_seq` in each.

### One station per vehicle run

v0.2b is single-session by contract: one ground-station process commands one
vehicle run. There is no command-source table, no client registry, and no
per-client state.

The drain owns the command socket, so the `recvfrom` and the record drain both
run on the drain thread and the latch below needs no synchronization.

```cpp
sockaddr_in   station_{};          // the accepted command source
bool          station_set_ = false;
std::uint64_t cmd_foreign_src_ = 0;
```

The first well-formed command datagram of the run latches `station_` from its
source address and port. Every later datagram is compared against that latch:
same address and port, it is accepted and forwarded to the classifier; anything
else is dropped before classification, counted in `cmd_foreign_src_`, and
answered with nothing. A foreign source gets no ack, because replying to an
unaccepted address turns the vehicle into a reflector and tells a stranger the
run exists.

Source identity therefore rides with the command by construction. The pending
non-abort slot, the deferred-ack slot, and every ack the drain emits all belong
to `station_`; there is exactly one accepted source for the life of the run, so
an ack can never be addressed anywhere else and no fallback path exists.

The cost, stated: a station that restarts and comes back on a new ephemeral port
is a foreign source for the rest of that vehicle run and its commands are
counted and ignored. That is the intended behavior for one station process per
vehicle run, and the operator restarts the run. `summary.json` reports
`cmd_foreign_src_`, so a station that silently changed its port shows up as a
number rather than as unexplained silence.

Changed from the prior draft, which kept an eight-entry `pending_src_` table
indexed by `cmd_seq & 7` with a `last_src_` fallback and an `ack_src_fallback`
counter. That is a multi-client mechanism, and v0.2b has one client.

### Ring overflow

The drain-to-control ring is 64 slots. When `try_push` fails the control thread
never sees the command, so the drain classifies exactly that one condition itself
and emits REJECTED_OVERFLOW with `state = reason = 0xFF`. This is the only
classification the drain does; everything else it forwards. `summary.json`
reports `cmd_ring_overflow`. Sixty-four slots at one command per cycle drains in
128 ms; an operator producing that many commands is a test, and
`tests/functional/test_command.py` is that test.

## Wire and transport

### Framing v1, restated here

Framing v1 is frozen and is defined in this document, not by reference: sync
0xEB90, version 1, u8 type, u16 length, u32 seq, CRC-32C over everything after
the sync word, one frame per datagram, max frame 512 bytes, max payload 498.
`ground/wire.py:18-31` and `src/telemetry.hpp:29-41` are the implementations of
record. Changed from the prior draft, which cited a gitignored spec for the
framing: a tracked release design may not point at a document a reader cannot
open.

### Serialization rule

Every payload is written and read **field by field, little-endian**, through
fixed-offset helpers. No payload is produced by `memcpy` of a native struct onto
the wire, and no payload is consumed by `memcpy` from the wire into a native
struct, in either language. That includes type 1, the frozen v0.2a telemetry
record: WIRE-1 is decided, and the conversion is specified below.

`src/wire.hpp`, new, header-only, with no dependency on any struct layout:

```cpp
inline void put_u8    (unsigned char* p, std::size_t o, std::uint8_t  v) noexcept;
inline void put_u16_le(unsigned char* p, std::size_t o, std::uint16_t v) noexcept;
inline void put_u32_le(unsigned char* p, std::size_t o, std::uint32_t v) noexcept;
inline void put_u64_le(unsigned char* p, std::size_t o, std::uint64_t v) noexcept;
inline void put_i64_le(unsigned char* p, std::size_t o, std::int64_t  v) noexcept
    { put_u64_le(p, o, static_cast<std::uint64_t>(v)); }
inline void put_f64_le(unsigned char* p, std::size_t o, double v) noexcept
    { put_u64_le(p, o, std::bit_cast<std::uint64_t>(v)); }
// get_u8, get_u16_le, get_u32_le, get_u64_le, get_i64_le, get_f64_le mirror them.
```

`put_u64_le` is eight shift-and-store statements. Shift-and-store beats "memcpy
per field, byte-swapped on big-endian" because it produces the same bytes on any
target with one code path: there is no big-endian branch that no test ever
executes. The signed conversions are well defined at C++20, which mandates two's
complement, and `CMakeLists.txt:8` sets `CMAKE_CXX_STANDARD 20`. `std::bit_cast`
needs `<bit>`; it is a compile-time reinterpretation, not a function call.

Cost, estimated rather than measured: the control cycle serializes `actuator_v1`
(7 fields, 48 bytes) and deserializes `sensor_v1` (7 fields, 44 bytes), about 100
shift-and-store instructions per cycle against a 2 ms period and a measured L5
execution p99.9 of 0.271 us
(`baselines/2026-08-29-pinned-timer-campaign/L5.r1.summary.json`, `exec_us`).
Capability 6's L8 execution histogram is the actual answer.

### Type 1: the frozen serializer converts (WIRE-1)

Owner ruling: convert. `src/telemetry.cpp:141-153` frames a `telem::Record` by
handing `&batch[i]` and `sizeof(Record)` to `encode_frame`, which copies 56
native bytes onto the wire. It becomes a field-by-field little-endian
serialization through the same `src/wire.hpp` helpers every other payload uses:

```cpp
unsigned char payload[56];
put_u64_le(payload,  0, r.tick);
put_i64_le(payload,  8, r.deadline_ns);
put_i64_le(payload, 16, r.woke_ns);
put_i64_le(payload, 24, r.done_ns);
put_f64_le(payload, 32, r.theta);
put_f64_le(payload, 40, r.cmd);
put_u64_le(payload, 48, r.drops);
const std::size_t len = encode_frame(kTypeTelemetry, seq_++, payload, 56, frame);
```

`put_f64_le` is `std::bit_cast` to `std::uint64_t` and eight shift-and-stores, so
every double reaches the wire bit for bit: no rounding, no normalization, no
numeric conversion, signalling NaNs and negative zero included. The drain thread
runs off the isolated core, so the cost lands nowhere the control cycle can see
it.

The frozen public representation is the contract; the `memcpy` is one
implementation of it and has no standing. What must not move, and what proves
each:

| must stay byte-identical | proof |
|---|---|
| all 56 payload bytes, in the order and at the offsets above | the assert battery below plus the C++ known-answer test in `tests/cpp/wire_tests.cpp` |
| the framed bytes: sync, version, type 1, length, seq, CRC-32C | the committed corpus files replay bit for bit |
| the schema string `telemetry_v1:tick:u64,...,drops:u64` and its hash `0xA871CD84` | `src/telemetry.hpp:32`, `:35-37` are not touched, and the hash gate recomputes it |
| every committed golden corpus file under `tests/golden/` | `tests/golden/generate.py` regenerates them and `git diff --exit-code` is empty |
| existing `.tvcrec` recordings written by a v0.2a binary | header version 1 and `schema_hash` are unchanged, so an existing recording decodes under the new build |
| decoder output, C++ and Python, field for field | `tests/unit/test_wire.py` and `./build/wire_tests` are unchanged tests run against the changed writer |

The gate is mechanical and it is capability 2's: regenerate the corpus, diff it,
and run both decoders. A byte that moves fails the PR. The cost is a diff in a
frozen file, and the benefit is one serialization discipline in the codebase and
no path where adding a field to `Record` changes the wire without changing the
schema string.

### Payload tables

All fields little-endian. Offsets are from the first byte of the payload, which
is frame byte 10. Every payload is naturally aligned with no interior padding.

**sensor_v1, type 4, 44 bytes, frame 58 bytes**

| offset | size | type | field | meaning |
|---|---|---|---|---|
| 0 | 8 | u64 | tick | sim tick, from 0 |
| 8 | 8 | i64 | t_send_ns | CLOCK_MONOTONIC in the sim immediately before the send; 0 in lockstep |
| 16 | 8 | f64 | theta | rad; read only when SAMPLE_VALID |
| 24 | 8 | f64 | omega | rad/s; read only when SAMPLE_VALID |
| 32 | 4 | u32 | flags | bit0 SAMPLE_VALID, bit1 EPISODE_END, bit2 CMD_PRESENT, bits 3-7 reserved 0, bits 8-15 opcode (1 ARM, 2 LAUNCH, 3 ABORT), bits 16-31 reserved 0 |
| 36 | 4 | u32 | cmd_seq | the in-band command's sequence when CMD_PRESENT, else 0 |
| 40 | 4 | u32 | sim_reason | the simulator's authoritative terminal reason; 0 unless EPISODE_END |

Changed from the prior draft: `sim_reason` is new and the payload grows from 40
to 44 bytes, because mandate correction 7.

An explicit field, not reserved bits, for three reasons. The frame contract says
decoders ignore reserved bits, so a reason carried there would be silently
dropped by a conforming older decoder, which is the exact failure correction 7
exists to prevent. The enum will grow, so a bit field would have to fix its width
now. And a named field appears in the schema string, so the schema hash changes
and a decoder built against the old schema fails the file-hash check loudly
instead of misreading. The cost is 4 bytes per sensor frame, 54 to 58 bytes on
the wire, 29 KB/s at 500 Hz. `sim_reason` is u32 rather than u8 plus three
padding bytes so the payload has no reserved hole to police and every field stays
naturally aligned; a native struct would be 48 bytes while the wire is 44, which
is another reason `sensor_v1` has no native struct.

`sim_reason` is nonzero exactly when EPISODE_END is set. The vehicle ignores
`sim_reason` on any frame without EPISODE_END.

**actuator_v1, type 5, 48 bytes, frame 62 bytes**

| offset | size | type | field | meaning |
|---|---|---|---|---|
| 0 | 8 | u64 | tick | the sensor tick this frame answers, `expected` |
| 8 | 8 | u64 | veh_tick | vehicle cycle index n |
| 16 | 8 | i64 | t_sensor_send_ns | echo of the consumed sample's `t_send_ns`; 0 if none, 0 in lockstep |
| 24 | 8 | i64 | t_veh_send_ns | CLOCK_MONOTONIC before the send; 0 in lockstep |
| 32 | 8 | f64 | delta | gimbal command, rad, clamped to the stop |
| 40 | 4 | u32 | status | byte0 state, byte1 reason, byte2 ladder (0 fresh, 1 coast, 2 neutral, 3 lost), byte3 ack (`0x80 \| ack_status` when this cycle produced an ack, else 0) |
| 44 | 4 | u32 | staleness | `expected - newest_consumed_tick`, saturating |

Served s2a is computed from `t_sensor_send_ns` and the vehicle's own `tx_ns`, and
discard age never leaves the vehicle, so correction 8 needs no field here.

**command_v1, type 2, 16 bytes, frame 30 bytes.** Free-run only.

| offset | size | type | field | meaning |
|---|---|---|---|---|
| 0 | 4 | u32 | cmd_seq | from 1, constant across retransmits; the dedupe key |
| 4 | 2 | u16 | opcode | 1 ARM, 2 LAUNCH, 3 ABORT; 0 and everything else invalid |
| 6 | 2 | u16 | flags | bit0 RETRANSMIT, bits 1-15 reserved 0 |
| 8 | 8 | u64 | effective_tick | the tick at which the command takes effect |

**ack_v1, type 3, 16 bytes, frame 30 bytes.** Free-run only.

| offset | size | type | field | meaning |
|---|---|---|---|---|
| 0 | 8 | u64 | applied_tick | the tick the command took effect; 0 if it did not |
| 8 | 4 | u32 | cmd_seq | the command being acknowledged |
| 12 | 2 | u16 | status | the status table under "Command protocol" |
| 14 | 1 | u8 | state | episode state at classification; 0xFF when not evaluated |
| 15 | 1 | u8 | reason | episode reason at classification; 0xFF when not evaluated |

0xFF in `state` and `reason` means the control thread never saw the command. Only
the drain-emitted REJECTED_OVERFLOW ack uses it.

**control_v1, type 6, 128 bytes, frame 142 bytes**

| offset | size | type | field | meaning |
|---|---|---|---|---|
| 0 | 8 | u64 | tick | `expected`; `tick_base` is 0 in lockstep |
| 8 | 8 | i64 | deadline_ns | `origin + n * period_ns`; 0 in lockstep |
| 16 | 8 | i64 | woke_ns | after the sleep returns |
| 24 | 8 | i64 | done_ns | end of cycle, after the ring push |
| 32 | 8 | i64 | sensor_send_ns | `t_send_ns` of the consumed sample; 0 if none |
| 40 | 8 | i64 | rx_ns | after the sensor drain returns |
| 48 | 8 | i64 | tx_ns | after the actuator send returns |
| 56 | 8 | u64 | sensor_tick | newest consumed sensor tick; 0xFFFFFFFFFFFFFFFF before the first |
| 64 | 8 | f64 | theta | consumed sample |
| 72 | 8 | f64 | omega | consumed sample |
| 80 | 8 | f64 | cmd | command sent this cycle |
| 88 | 8 | f64 | i_state | PID integrator after this cycle |
| 96 | 8 | f64 | d_prev | PID derivative filter state after this cycle |
| 104 | 8 | u64 | drops | cumulative ring `try_push` failures before this record |
| 112 | 4 | u32 | staleness | `expected - sensor_tick`; `n + 1` saturating before the first consumed sample |
| 116 | 4 | u32 | ack_cmd_seq | the command acknowledged this cycle; 0 if none |
| 120 | 1 | u8 | rx_count | datagrams classified this cycle, carry buffer included on cycle 0 |
| 121 | 1 | u8 | discarded_old | of those, discarded as not newer than an earlier cycle's consumed sample |
| 122 | 1 | u8 | discarded_superseded | of those, replaced by a newer frame in the same cycle |
| 123 | 1 | u8 | discarded_other | of those, non-finite rejections plus excessive-skew discards |
| 124 | 1 | u8 | state | episode state |
| 125 | 1 | u8 | reason | episode reason |
| 126 | 1 | u8 | flags | bit0 FRESH_SAMPLE, bit1 TX_OK, bit2 CMD_APPLIED, bit3 COAST, bit4 NEUTRAL, bit5 RX_OVER_BOUND, bit6 ACK_PRESENT, bit7 NONFINITE_REJECTED |
| 127 | 1 | u8 | ack_status | ack_v1 status code, meaningful when ACK_PRESENT |

Changed from the prior draft: `rx_count` narrows from u32 to u8 and the three
freed bytes become the per-cycle discard counters, because mandate correction 8
needs the discard categories reconstructable per cycle from the recording alone.
Changed again from the protocol area's draft, whose third counter was
`discarded_future`: a parked future frame that expires was accepted in an earlier
cycle and is not in this cycle's `rx_count`, so it cannot sit in a field the
decoder bounds by `rx_count`. `future_expired` is a run-level counter only.
Non-finite rejections needed a count rather than a flag, because two non-finite
datagrams in one cycle are otherwise indistinguishable from one; flags bit7
NONFINITE_REJECTED stays as a cheap presence flag.

The decoder asserts `rx_count <= 9` and
`discarded_old + discarded_superseded + discarded_other <= rx_count`.

Total size stays 128 bytes, so the 4096-slot ring stays 512 KiB and the rlimit
accounting is unchanged. The record carries no "was this cycle inside the
recorded timing window" bit; that predicate is
`tick - episode.tick_base >= config.warmup`, evaluated offline from
`summary.json`. Per-cycle malformed counts are not in the record: a nonzero
malformed total is vehicle exit 6 and the run is not publishable, so per-cycle
detail would never be read.

### Schema strings and hashes

```
telemetry_v1:tick:u64,deadline_ns:i64,woke_ns:i64,done_ns:i64,theta:f64,cmd:f64,drops:u64
command_v1:cmd_seq:u32,opcode:u16,flags:u16,effective_tick:u64
ack_v1:applied_tick:u64,cmd_seq:u32,status:u16,state:u8,reason:u8
sensor_v1:tick:u64,t_send_ns:i64,theta:f64,omega:f64,flags:u32,cmd_seq:u32,sim_reason:u32
actuator_v1:tick:u64,veh_tick:u64,t_sensor_send_ns:i64,t_veh_send_ns:i64,delta:f64,status:u32,staleness:u32
control_v1:tick:u64,deadline_ns:i64,woke_ns:i64,done_ns:i64,sensor_send_ns:i64,rx_ns:i64,tx_ns:i64,sensor_tick:u64,theta:f64,omega:f64,cmd:f64,i_state:f64,d_prev:f64,drops:u64,staleness:u32,ack_cmd_seq:u32,rx_count:u8,discarded_old:u8,discarded_superseded:u8,discarded_other:u8,state:u8,reason:u8,flags:u8,ack_status:u8
```

A schema string is the type name, a colon, then `field:type` for every field in
offset order, comma separated, ASCII, no spaces. Every hash below is recomputed
at capability 2 from these strings with `google-crc32c` in `ground/wire.py` and
with `telem::crc32c` in `src/telemetry.cpp`, and both must reproduce the table.
The values here are probe numbers from a stdlib CRC-32C whose known answers
reproduce: the four RFC 3720 appendix B.4 vectors and the standard 123456789
check value in `tests/unit/test_wire.py:10-14`, plus 0xA871CD84, plus all five
hashes the prior draft computed with `google-crc32c`.

| type | name | payload | frame | schema hash | changed |
|---|---|---|---|---|---|
| 1 | telemetry_v1 | 56 | 70 | 0xA871CD84 | no, and must not |
| 2 | command_v1 | 16 | 30 | 0x7F802902 | no |
| 3 | ack_v1 | 16 | 30 | 0x3D42AF39 | no |
| 4 | sensor_v1 | 44 | 58 | 0xD23A4196 | yes, was 0x3A888FD5 |
| 5 | actuator_v1 | 48 | 62 | 0x25573656 | no |
| 6 | control_v1 | 128 | 142 | 0xADFA94C8 | yes, was 0xFC5B9E85 and then 0x6B87B5CF |

Changed from the protocol area's draft: `control_v1` is 0xADFA94C8, not
0x6B87B5CF, because renaming `discarded_future` to `discarded_other` changes the
schema string. 0x6B87B5CF is the hash of the superseded string and is recorded
here only so a reader who saw it knows which one it was.

The type-1 hash 0xA871CD84 survives unchanged, so `tests/golden/manifest.json`,
`tests/unit/test_wire.py:17-18`, `src/telemetry.hpp:32` and every committed
corpus file stay byte-identical.

Recording header `schema_hash` (u32 at header offset 12, header version 1
unchanged) is the CRC-32C of the **file schema string**: the `;`-joined per-type
schema strings of the types the file may contain, in ascending type code. A file
holding only type 1 joins a list of one, which is why its hash is still the type-1
hash.

| file | types | schema_hash |
|---|---|---|
| `<label>.telemetry.tvcrec` (harness with the default record, unchanged) | {1} | 0xA871CD84 |
| `<label>.inputs.tvcrec` (sim, every sensor frame sent) | {4} | 0xD23A4196 |
| `<label>.control.tvcrec` (harness with `--record=control`, and vehicle) | {6} | 0xADFA94C8 |
| `<label>.ground.tvcrec` (station) | {6} | 0xADFA94C8 |

Changed from the prior draft, which bound `<label>.control.tvcrec` to the vehicle
alone: L7 is harness mode writing 128-byte `control_v1` records, so the harness
writes that file too.

Commands and acks go to `<label>.commands.jsonl`, never into a mixed-type
recording: they carry a different sequence space and the decoder's single-stream
gap rule would report nonsense over them.

### Decoder rules

`ground/wire.py` gains `SCHEMAS`, `SCHEMA_HASHES`, `FILE_SCHEMAS`,
`PAYLOAD_SIZES`, `encode_payload`, `decode_payload` and
`decode_datagram(data, accepted_types)`; it keeps `SCHEMA` and `SCHEMA_HASH` as
type-1 aliases and widens `TYPES` from `(1, 2, 3)` to `(1, 2, 3, 4, 5, 6)`
(`ground/wire.py:21`). `src/telemetry.cpp:81` widens its type check from
`type >= 1 && type <= 3` to 1..6. `tests/unit/test_wire.py:48` changes
`(0, 4, 255)` to `(0, 7, 255)` in capability 2, since type 4 becomes valid, and
the PR body says so.

Datagram decode, strict, no resync, one frame per datagram:

1. bytes 0..1 are `0x90 0xEB`, else `bad_sync`
2. version byte is 1, else `bad_version`
3. type is in the accepted set for this socket, else `bad_type`
4. `length` equals `PAYLOAD_SIZES[type]` exactly, else `bad_length`
5. the datagram is exactly `14 + length` bytes, else `bad_length`
6. CRC-32C matches, else `bad_crc`

| socket | accepted types |
|---|---|
| vehicle sensor/actuator (fd A) | {4} |
| vehicle command (fd B, drain-owned) | {2} |
| sim | {5} |
| station telemetry (fd T) | {6} |
| station command (fd G) | {3} |

`PAYLOAD_SIZES = {1: 56, 2: 16, 3: 16, 4: 44, 5: 48, 6: 128}`. Any failure
discards the datagram and increments the named counter. A nonzero total at end of
run is vehicle exit 6, link integrity failed, and the run is not publishable: on
loopback with a CRC there is no legitimate way to see one.

`read_recording` enforces the payload length against the record type named by the
header's schema hash, so a wrong-size type-1 payload stays as loud as it is
today.

### Ports and peer discovery

`--port-base=B` is a **production default only**, and it is an alias that expands
to `--sensor-port=B --bind-port=B+1 --command-port=B+2 --telemetry-port=B+3`.
Tests never use it. 24000 through 24003 sit under the Linux default ephemeral
floor of 32768 (`sysctl net.ipv4.ip_local_port_range`, confirmed on the
measurement machine before the campaign), so the kernel never hands one to an
unrelated client.

| port | bound by | flag | purpose |
|---|---|---|---|
| 24000 | vehicle, control thread, fd A | `--sensor-port=24000` | receive sensor (type 4), send actuator (type 5) |
| 24001 | sim | `--bind-port=24001` | send sensor, receive actuator |
| 24002 | vehicle, drain thread, fd B | `--command-port=24002` | receive command (type 2), send ack (type 3) |
| 24003 | station, fd T | `--telemetry-port=24003` | receive control records (type 6) |
| ephemeral | station, fd G | always `bind(0)` | send command, receive ack |
| ephemeral | vehicle drain, fd C | never bound, `connect` only | send control records to the station |

Changed from the prior draft: `base+3` was unused and `base+4` was the station's
telemetry port; the sink moves down to `base+3` and the base loses a port,
because mandate correction 11 says assign the unused port or remove it, and
renumbering removes the hole. The prior draft's claim that a functional test can
"bind port 0 to pick a free base" is withdrawn. Probe, two runs on this Mac: the
first `bind(0)` returned 51790 and then 52319; in both runs an explicit bind of
the next four ports succeeded immediately, and none of 32 further `bind(0)` calls
landed adjacent to the first. `bind(0)` allocates one port and reserves nothing.

Peer discovery needs three facts known at startup and one learned:

| link | how the sender learns the destination |
|---|---|
| sim to vehicle sensor | `--vehicle=HOST:PORT`, from the vehicle's ready line |
| vehicle to sim actuator | **learned**: `connect` to the source address of the first sensor datagram |
| station to vehicle command | `peer HOST:PORT` on the station's stdin, from the vehicle's ready line |
| vehicle drain to station telemetry | `--ground=HOST:PORT`, from the station's ready line |
| vehicle drain to station ack | the `recvfrom` source address of the command datagram |

The vehicle's fd A is bound at startup and connected exactly once, immediately
after the first sensor datagram arrives and before the control loop begins. In
free-run that datagram is the bounded blocking origin wait; in lockstep it is the
first blocking receive. Both are outside the control cycle. After the `connect`
the kernel filters foreign sources and `ECONNREFUSED` reaches the vehicle. The
downside, stated plainly: a stray datagram arriving before the sim's first frame
would fix the wrong peer. On loopback under a runner that starts one sim, a run
whose peer is wrong shows up as zero received frames and terminates SENSOR_LOST.

### The ready line

One grammar for all three modes, printed before RT setup, the only stdout
contract:

```
ready mode=<harness|lockstep|freerun> sensor_port=<S> command_port=<V> pid=<n> bin=<resolved path> consts=0x<8 lowercase hex>
```

`sensor_port` and `command_port` are the actually-bound ports, whether they came
from `--port-base`, from the per-socket flags, or from `bind(0)`;
`command_port=0` when the socket is not opened. `--port-base` never appears on
the ready line. Changed from the prior draft, which printed `base=24000` in
lockstep and `sensor_port=`/`command_port=` in free-run: under the ephemeral
strategy every socket binds port 0, and a lockstep ready line carrying `base=`
leaves the runner unable to build the sim's `--vehicle=HOST:PORT`.

`scripts/run_scenario.py` waits for the line with a 10 s wall limit (runner exit
6), parses `key=value` pairs, and compares `consts` against
`sim.control_ref.DIGEST` before starting the sim (runner exit 7 on mismatch). No
test parses any other line of vehicle stdout.

### Ephemeral strategy for functional tests

Three steps, and the runner never guesses a port:

```
# 1. station first; it prints its bound ports and then waits
python3 -m ground.station --telemetry-port=0 --command-port=0 --no-tty
    -> ready station telemetry_port=<T> command_port=<G>

# 2. vehicle second, told where to send telemetry
build/tvc_harness --mode=freerun --sensor-port=0 --command-port=0 \
    --telemetry --record=control --ground=127.0.0.1:<T>
    -> ready mode=freerun sensor_port=<S> command_port=<V> pid=<n> bin=<path> consts=0x<8 hex>

# 3. tell the station where the vehicle is, then start the sim
echo "peer 127.0.0.1:<V>" >> station stdin
python3 -m sim.run_sim --mode=freerun --scenario=S2-gust \
    --vehicle=127.0.0.1:<S> --bind-port=0
```

Runs without a station, which is every sweep row and most tests, drop steps 1 and
3 and pass no `--ground`. The sim's bound port is never published because nobody
needs it: the vehicle learns the sim's address from the first datagram.

### Sockets

`socket(AF_INET, SOCK_DGRAM | SOCK_NONBLOCK, 0)`; `SO_RCVBUF` 256 KiB on the
vehicle's receiving sockets (about 341 small datagrams, 0.68 s at 500 Hz);
`SO_SNDBUF` default; no `SO_REUSEADDR`, so a bind failure is another instance,
exit 2, `applied.link = false`.

The hot path may: `recvmmsg` and `send` with `MSG_DONTWAIT` on the connected
sensor and actuator socket, measured inside the exec histogram; CRC-32C over at
most 142 bytes; integer and float math; `clock_gettime(CLOCK_MONOTONIC)`; the
absolute-deadline `clock_nanosleep` at the cycle boundary; ring `try_push`; fixed
stack buffers. It may not allocate, lock, block, format, open or close a
descriptor, read CLOCK_REALTIME, write a file, or grow a container. The existing
`guard::Cycle` scope covers the link work under `--alloc-guard=abort`.

### Sequence reconciliation

Sequence gaps in the vehicle's receive stream cannot see trailing loss: if the
last three datagrams of a run are dropped, no later sequence ever arrives to open
the gap. Gaps are a diagnostic. **The simulator's transmission counters are
authoritative**, reconciled at end of run against the vehicle's receive counters.

One name per quantity, in every document and every script. Changed from the prior
draft, in which the execution and protocol sections carried three spellings per
quantity and two scripts were specified to read both.

| counter | owner | windows | definition |
|---|---|---|---|
| `generated` | sim | episode | sensor frames built: the free-run prologue plus one per sim tick in free-run, one per sim tick in lockstep |
| `intentionally_lost` | sim | episode | the frame was not sent for a loss-model reason: the draw said drop and no override sent it, or a blackout window dropped a frame the draw passed |
| `forced_transmit` | sim | episode | diagnostic subset of `transmitted`: the draw said drop and an override sent it anyway; in v0.2b a tick before a scenario's `loss_start_tick`, or the free-run prologue |
| `forced_drop` | sim | episode | diagnostic subset of `intentionally_lost`: the draw said pass and a blackout window dropped it anyway |
| `transmitted` | sim | episode | successful `sendto` calls of episode frames |
| `terminal_copies_sent` | sim | episode | free-run terminal grace copies; outside `generated` and `transmitted` |
| `received` | vehicle | episode, recorded | well-formed type-4 datagrams the decoder accepted, counted in the cycle they arrived |
| `consumed` | vehicle | episode, recorded | observations the controller used; FRESH_SAMPLE set |
| `discarded_old` | vehicle | episode, recorded | class 5 |
| `discarded_superseded` | vehicle | episode, recorded | class 6 loser |
| `discarded_nonfinite` | vehicle | episode, recorded | class 2 |
| `discarded_skew_excess` | vehicle | episode, recorded | class 8; nonzero is exit 6 |
| `discarded_duplicate` | vehicle | episode, recorded | class 3 |
| `discarded_tick_conflict` | vehicle | episode, recorded | class 4; nonzero is exit 6 |
| `future_expired` | vehicle | episode, recorded | a parked frame aged past `expected + skew_max` |
| `future_parked` | vehicle | state | the future ring's occupancy, 0 through `skew_max` |
| `malformed` | vehicle | episode | sum of the six `bad_*` counters |
| `unexplained_missing` | runner | episode | `transmitted_in_window - received` |
| `trailing_transmitted` | runner | episode | `transmitted - transmitted_in_window` |

Redefining `intentionally_lost` and adding `forced_drop` is changed from the
prior draft, whose two override counters did not partition `generated`: a
blackout turns a pass into a drop, the opposite direction from
`forced_transmit`, and landed silently inside `intentionally_lost`. With the
definitions above, `generated = intentionally_lost + transmitted` holds on every
tick including S6-blackout's 1000 through 1030, and both override counters stay
pure diagnostics that no identity depends on. `forced_transmit` loses its
terminal-frame use, which under the 12 loss-subject terminal copies has no
override left to count.

Uplink identities, windowed:

```
generated             = intentionally_lost + transmitted
transmitted_in_window = received + unexplained_missing
trailing_transmitted  = transmitted - transmitted_in_window
```

`transmitted_in_window` counts sim transmissions of sensor ticks in
`[tick_base, last_received_tick]`, read from `replay.json`'s `first_tick` and
`last_tick`. `unexplained_missing` must be zero for a publishable run.
`trailing_transmitted` is reported and gates nothing; it is bounded by
`terminal_copies_sent + G_sim`. Which ending produces which boundary term: a
vehicle-first ending leaves one or two frames in flight; a sim-first ending
leaves up to `terminal_copies_sent - 1`.

Changed from the prior draft, which stated `transmitted = received +
unexplained_missing` over the whole episode with no boundary term and also
required `unexplained_missing == 0` for publication. On the normal L8 ending the
vehicle's `--cycles` horizon fires first and its terminal loop does not receive,
so the sim's remaining copies can never arrive and no L8 run would be
publishable. The prior draft's sentence claiming every terminal copy after the
first lands in `discarded_old` is deleted: it is true only of the copies that
arrive before the vehicle terminates.

Downlink, symmetric:

```
actuator_generated   = one per vehicle episode cycle
actuator_transmitted = actuator_generated - actuator_tx_fail          (EAGAIN)
actuator_transmitted_in_window = actuator_received + actuator_unexplained_missing
actuator_received    = actuator_applied + downlink_intentionally_lost + actuator_superseded
```

`actuator_superseded` is new: an accepted actuator datagram that survived the
down draw and was not the largest tick among that sim tick's survivors. Changed
from the prior draft, whose downlink identity had no such term and therefore
failed on any sim tick that accepted two datagrams, which over a 300,000-cycle L8
run is certain. `trailing_actuator_transmitted` is bounded by the vehicle's
terminal-copy count `R`.

Lockstep is different and the split is deliberate: no datagram is dropped by
design, so `generated == transmitted` and uplink loss appears as
SAMPLE_VALID = 0 inside frames that arrive. A lockstep resend increments
`transmitted`, `received` and `discarded_duplicate` together, so the identity
holds.

## link_sim and RNG

### Loss model

Independent Bernoulli per packet event: `u = stream.next_double()`,
`drop = (u < p)`. `p = 0.0` never drops and `p = 1.0` always drops, with no
special case. Independent per direction with separate streams and separate
probabilities: `--loss P` sets both, `--loss-up` and `--loss-down` override.
"30% packet loss" means `p_up = p_down = 0.30`, so 51% of ticks lose at least one
frame and 9% lose both.

| | uplink loss | downlink loss |
|---|---|---|
| lockstep | sensor frame sent with SAMPLE_VALID = 0, theta and omega zero, tick real, seq consumed | the sim reads the actuator frame (state, reason, staleness honored) and delivers `None` to the actuator, which holds |
| free-run | the sim does not call send; the built frame's seq is consumed so the wire shows a gap | the sim receives and discards; `None` reaches the actuator when no survivor remains |

### The generator

SplitMix64, one 64-bit state per stream, identical arithmetic in Python (masked)
and C++ (`uint64_t`):

```python
GOLDEN  = 0x9E3779B97F4A7C15
MASK    = 0xFFFFFFFFFFFFFFFF
TWO_M53 = 1.0 / 9007199254740992.0        # an exact division; 0x1.0p-53 in C++

def mix(z):
    z &= MASK
    z = ((z ^ (z >> 30)) * 0xBF58476D1CE4E5B9) & MASK
    z = ((z ^ (z >> 27)) * 0x94D049BB133111EB) & MASK
    return z ^ (z >> 31)

def next_u64(self):
    self.state = (self.state + GOLDEN) & MASK
    return mix(self.state)

def next_double(self):
    return (self.next_u64() >> 11) * TWO_M53
```

`MASK` is written as a hex literal and `TWO_M53` as that division, never
`2**64 - 1` or `2.0**-53`, so `tests/unit/test_sim_purity.py`'s grep for `**`
stays clean and the constant is exact in both languages.

### Stream identities

Names are lowercase ASCII, dot separated, and appear in exactly that spelling in
code, in `replay.json`, and in every test key. The index is what the derivation
consumes and is never reassigned.

| index | name | v0.2b | drawn |
|---|---|---|---|
| 0 | `link.loss.up` | instantiated | once per sensor frame in both modes; the free-run prologue takes draw 0 |
| 1 | `link.loss.down` | instantiated | once per tick in lockstep; once per accepted actuator datagram in free-run |
| 2 | `sensor.noise` | reserved, not instantiated | never |
| 3 | `actuator.fault` | reserved, not instantiated | never |
| 4 | `environment.disturbance` | reserved, not instantiated | never |
| 5 | `parameter.sampling` | reserved, not instantiated | never |
| 6 | `scenario` | reserved, not instantiated | never |

```python
STREAMS = ("link.loss.up", "link.loss.down", "sensor.noise", "actuator.fault",
           "environment.disturbance", "parameter.sampling", "scenario")

def stream_state(master, name):
    i = STREAMS.index(name)          # raises on an unknown name
    return mix((master + (i + 1) * GOLDEN) & MASK)
```

Changed from the prior draft, which shipped three incompatible index tables
across its plan, protocol and physics sections and two spellings of every name.
The index order above is the mandate's category order; the dotted spelling keeps
stream identities visually distinct from the `-v<N>` model identifiers and is the
one the reproducibility contract records. No known answer moves, because a
stream's state is a function of its index alone.

Adding a stream never shifts an existing stream's sequence, because seeding is
index-derived: each stream's start state depends on the master seed and its own
index, so a stream that did not exist yesterday cannot consume a draw that
belonged to another, and cross-stream draw order does not enter any single
stream's sequence. `tests/unit/test_rng.py` asserts it rather than leaving it as
an intention: the first eight draws of streams 0 through 3 are identical whether
four or seven streams are instantiated, and across masters 1 to 64 and all seven
indices the 448 eight-draw prefixes are distinct with no shifted-window aliases.

Deriving from a frozen index rather than from a hash of the name means a typo
raises instead of silently creating an eighth stream. Reserving all seven indices
now means instantiating `sensor.noise` in a later release cannot shift a single
draw of `link.loss.up`.

Only the sim draws. The vehicle contains no RNG. `--seed=N`, u64, default 1.

### Draw order

In lockstep, one draw per live stream per tick, unconditionally, before any
decision that could skip the send: `link.loss.up`, then `link.loss.down`. Each
stream's position is therefore a pure function of the tick index.

In free-run, `link.loss.up` draws once per frame (the prologue is frame 0) and
`link.loss.down` draws once per accepted actuator datagram in receive order.
Free-run stream position is not tick-indexed, which is why seed reproduction is
claimed only in lockstep.

A blackout window, a `loss_start_tick`, or the free-run prologue takes its draw
and then overrides the outcome. A resend takes no draw, in either direction: a
resend is not a packet event. Pinned by a conformance test that runs in lockstep
only, with a blackout and a forced resend, asserting the end-of-run stream
states.

Changed from the prior draft, whose protocol section stated the per-tick rule
universally while its execution section drew the free-run `down` stream per
datagram, and whose lockstep step A and free-run step 5 still drew two streams
this release removed.

## Latency and frame accounting

### One host, one clock

Every cross-process subtraction below assumes both processes read the same
`CLOCK_MONOTONIC` on one host. That holds for the v0.2b topology, which is three
processes on 127.0.0.1. On two hosts every such difference is meaningless without
time transfer and only the sim's round trip survives; `docs/methodology.md`
carries that sentence, added at capability 6.

### Served sensor-to-actuator latency

For an observation the controller **actually consumed**:

```
served_s2a = tx_ns - sensor_send_ns      on records with FRESH_SAMPLE set
```

From the sim's stamp immediately before its send to the vehicle's stamp
immediately after the actuator send returns. `done_ns` is not the endpoint
because it includes the ring push. The distribution is `latency_us`, and it is
the served distribution and nothing else.

Changed from the prior draft, which fed one sample per **sent** datagram into a
single histogram, discarded datagrams included, because mandate correction 8. A
datagram that was superseded and never reached the controller did not receive an
actuator response, and counting it as though it had inflated the tail the gate
reads.

### Discard age

For a received observation the controller did not consume:

```
discard_age = rx_ns - t_send_ns          per discarded datagram
```

`rx_ns` is stamped once, after the receive batch returns, and classification
happens immediately after, so the discard decision costs no extra clock read.
`discard_age_us` is a separate distribution with its own CSV and its own summary
block. It is reported next to served s2a and is never gated. The four classes
that contribute a sample are old, superseded, non-finite and excessive skew;
duplicate, tick conflict and future expiry contribute none.

### Windows and count identities

Histograms start at warmup, the same gate jitter and execution already use
(`src/main.cpp:420-426`). The count identities are T1 through T4 under "Ticks,
windows and modes", and they are stated once there. `scripts/latency.py`
recomputes them from `<label>.control.tvcrec` plus `summary.json` and fails on a
mismatch. It refuses any summary whose mode is not `"freerun"` or that
`discipline_problem` rejects.

Changed from the prior draft, which asserted
`latency_us.count == replay.json sent_sensor_frames`, comparing a post-warmup
histogram against a full-episode frame count.

### Coverage, and what it replaces

```
served_coverage = consumed_recorded / recorded_cycles
```

The fraction of recorded cycles that produced a served sample. It is a
vehicle-only quantity and needs no sim counter.

The prior draft claimed the latency series was coordinated-omission-free by
construction, because every sent datagram contributed a sample. Under correction
8 that claim is gone: the served series covers consumed observations only, so a
slow cycle whose sample got superseded contributes nothing to it. Three things
close the gap and the release text must say so together: the discard-age
distribution, which is where those samples went; the coverage threshold, which
bounds how many there can be; and the reconciliation identity, which proves none
went missing.

### The gate rule

Served s2a p99.9 may be used as evidence only when all four hold:

| clause | value | source |
|---|---|---|
| `served_coverage >= 0.99` on a row whose peer ran at zero loss | 0.99 | declared below |
| `unexplained_missing == 0`, both directions | 0 | `<label>.reconcile.json` |
| `malformed == 0` | 0 | `summary.json` `link` |
| `discipline_problem(summary)` passes | | `scripts/bench_gate.py` |

Then the budget: `latency_us["p99.9"] <= 1000` and `latency_us["max"] <= 2000`,
half the 2000 us period and one full period. Half a period because the plant
model assumes the command lands inside the tick it was computed for; exceeding a
full period applies it to a state one tick older than the controller assumed.
The budget is unchanged from the prior draft, and it now constrains a narrower
and faster distribution since the discards moved out. `docs/results.md` says so
rather than reporting an apparently improved number as an improvement.

`served_coverage` is evaluated only on an L8 row whose peer ran at `--loss=0.0`.
A row with nonzero loss is timing evidence and never coverage evidence, and at
any nonzero `p_up` the coverage ceiling is `1 - p_up`. `bench_gate.py` exits 1
printing `<path>: --served-coverage-min against a row whose peer loss is <p>`
rather than reporting a coverage failure that says nothing about the vehicle.
The L8 sweep row's peer command line is written into the sweep-levels table under
"CI and bare-metal acceptance", so the gate has no unstated input. Changed from
the prior draft, which declared the threshold "at 0% loss" and never said which
run that was.

**Justifying 0.99.** The fresh-tick fraction at 0% loss has never been measured,
because no free-run run exists yet. The arithmetic that makes 0.99 meaningful: at
500 Hz over 300,000 recorded cycles it permits 3,000 cycles with no served
sample. At a 400 us offset, with the vehicle's own observed p99.9 wakeup jitter
at 16.5 us, every one of those cycles requires a sim-side scheduling event longer
than the offset. The sim is CPython under SCHED_OTHER on the housekeeping CPUs,
so such events exist; 1% is the ceiling at which the served series still
describes the control loop rather than the sim's scheduler. The offset itself is
not assumed: it is selected by the predeclared calibration below, which runs
before the release campaign.

### Phase-offset calibration (PHASE-1)

Owner ruling: sweep the offset, as a predeclared calibration experiment that runs
**before** the final L7/L8 evidence campaign. It is not a post-hoc adjustment of
the release campaign, its runs are not release evidence, and every rule below is
fixed before the first calibration run starts.

**The grid.** `--phase-us` at 200, 400 and 800. Exactly three values. The grid is
not extended after the result is seen.

**Run length and repeats.** Three runs per offset, `--cycles 300000 --warmup
5000` at 500 Hz, the same per-run length as the release campaign so coverage is
measured on the same window shape. Nine runs, interleaved by offset as
`for repeat: for offset:` so drift over the session is shared across the arms.

**Peer configuration.** The L8 sweep row's peer at zero loss, the command line
written into the sweep-levels table verbatim:
`python3 -m sim.run_sim --mode=freerun --scenario=S1-hold --seed=1 --loss=0.0
--ticks={total_plus_margin} --vehicle=127.0.0.1:{sensor_port} --bind-port=0`.
A calibration run against a lossy peer is void, because at any nonzero `p_up`
the coverage ceiling is `1 - p_up`.

**Machine state.** The pinned-timer discipline of record, with
`discipline_problem` clean on every summary and every summary carrying
`"mode": "freerun"`. A run that fails either is discarded and repeated, and the
discard is recorded.

**Measurement window.** The recorded timing window, cycles `n` in
`[warmup, total)`, the same window T1 through T4 use. Coverage reads
`link_recorded`, never `link`.

**Served-coverage calculation.** `served_coverage = consumed_recorded /
recorded_cycles`, one value per run, computed by `scripts/latency.py` from
`summary.json` and cross-checked against the recording.

**Selection rule, evaluated per offset over its three runs.** An offset
qualifies when all five hold:

1. every run has `served_coverage >= 0.99`;
2. the median of the three `served_coverage` values is `>= 0.995`;
3. `unexplained_missing == 0` in both directions on every run
   (`<label>.reconcile.json`);
4. `malformed == 0` on every run (`summary.json`, `link`);
5. the served-latency budget holds on every run: `latency_us["p99.9"] <= 1000`
   and `latency_us["max"] <= 2000`.

**Select the smallest qualifying offset.** The offsets are distinct integers, so
the rule has no tie and no judgement in it. `scripts/latency.py --calibration`
prints the nine rows, the per-offset verdict, and the selected value, and exits 1
when nothing qualifies.

**If nothing qualifies, stop.** Do not extend the grid, do not add repeats, and
do not weaken a threshold after seeing a result. The failure is a design defect:
amend this document, get the amendment reviewed, and re-run the calibration under
the amended rule.

**Freezing the result.** The selected offset is written into this document, as
the `--phase-us` default and in the sweep-levels table, and into the release's
internal log entry, in a PR that merges **before** the first release-campaign run.
The calibration runs are committed as
`baselines/2026-09-XX-phase-calibration/`, marked calibration in their own README
line, never used as a gate baseline, and never counted as release evidence.
`docs/results.md` reports the selected offset and its measured coverage as
calibration, tier 3, in a paragraph separate from the campaign.

Until the calibration runs, `--phase-us` defaults to 400 and every number in this
document that depends on the offset is a design estimate.

### Decomposition

```
uplink wait     = rx_ns - sensor_send_ns
vehicle compute = tx_ns - rx_ns
uplink wait + vehicle compute == served_s2a      exactly; rx_ns cancels
```

Report percentiles of each component separately. Never add two percentiles and
call the sum a latency: `p99.9(a) + p99.9(b)` is not `p99.9(a + b)`.
`docs/results.md` carries the three distributions and no sum.

Downlink is the sim's round trip only, `t_recv_ns - tx_ns` measured sim-side from
the actuator echo, written to `replay.json` as `latency_roundtrip_us`. It is a
diagnostic, not evidence: the sim is not a real-time process.

### What lockstep refuses

`stats::LoopStats::record` is never called. `summary.json` carries
`"mode": "lockstep"` and `"jitter_us": null`, `"exec_us": null`,
`"latency_us": null`, `"discard_age_us": null`, `"cycles": 0`. The jitter,
execution, latency and discard-age CSVs are not written. `null` rather than
zeros, so a consumer that tries to plot or compare a lockstep summary fails with
a `TypeError` instead of publishing zeros. Every wire timestamp is 0 in lockstep,
so served s2a is undefined there by construction.

## Scenarios and acceptance

### Scenario schema, tvc-scenario-v1

`sim/scenarios/<id>.json`, validated by `sim/scenario.py`. Fields: `ticks`,
`theta0`, `omega0`, `gusts` (list of `[start_tick, end_tick, alpha_g]`, resolved
to `tau_d = k_a * alpha_g` outside the plant), `loss_up`, `loss_down`,
`loss_start_tick`, `blackout_up`, `blackout_down` (`[start, end]`, forced drop,
draw still taken), `commands` (list of `{tick, opcode}`, in-band,
`effective_tick = tick + 50`), `auto_arm`. The disturbance schedule is
tick-indexed and consumes no RNG.

One validation rule is new: **no scenario may schedule a command on a tick where
another command's `effective_tick` falls due.** `sim/scenario.py` rejects a file
that violates it. The rule exists because the per-cycle order classifies an
arriving command before applying a due pending one, so a scenario that does both
on one tick depends on that order for its outcome.

### The stabilization predicate

    settled  <=>  for every tick k in [T-W, T-1]:
                      |theta_k| <= THETA_SETTLE  and  |omega_k| <= OMEGA_SETTLE

    THETA_SETTLE = 0.02   rad     (kept from the prior draft)
    W            = 1000   ticks   (kept, 2.000 s at 500 Hz)
    OMEGA_SETTLE = 0.02   rad/s   (new, mandate correction 13)

**Choosing `OMEGA_SETTLE`.** Two facts bound it from opposite sides.

The residual motion in the final window is four orders of magnitude below any
plausible threshold. Max `|omega|` over the final 1000 ticks, S2-gust, 200 seeds
per case (probe: `python3 probe.py omega 200`):

| case | n | min | p50 | p95 | max |
|---|---|---|---|---|---|
| p = 0.00, D_eff = 0 | 200 | 1.292e-06 | 1.292e-06 | 1.292e-06 | 1.292e-06 |
| p = 0.00, D_eff = 1 | 200 | 1.303e-06 | 1.303e-06 | 1.303e-06 | 1.303e-06 |
| p = 0.30, D_eff = 0 | 200 | 2.274e-05 | 3.819e-05 | 4.956e-05 | 6.052e-05 |
| p = 0.30, D_eff = 1 | 200 | 2.286e-05 | 3.820e-05 | 5.010e-05 | 5.968e-05 |

Pooled over the 400 passing runs at `p = 0.30`, max `|omega|` is 6.0518e-05
rad/s. Max `|theta|` over the same window is p50 1.610e-05 and max 2.458e-05 at
`D_eff = 0`, which against `THETA_SETTLE = 0.02` is a margin of 800x. The
attitude clause alone was never going to fail a passing run.

The closed-loop relation near equilibrium bounds it from the other side. The
dominant pole pair is `-9.589298 +- 7.223223j`, so `omega_n = 12.0054 rad/s` and
`zeta = 0.7987`. A sustained oscillation of amplitude `A` at frequency `w` has
`max|omega| = A*w`. An oscillation that fills the attitude band, `A = 0.02`, at
the closed-loop natural frequency would show `max|omega| = 0.2401 rad/s`. Setting
`OMEGA_SETTLE` there would make the clause vacuous.

`OMEGA_SETTLE = 0.02 rad/s`. Against the evidence: 330x above the worst `|omega|`
observed in the 400-run campaign. Against the failure it exists to catch:
`A*w <= 0.02` with `A = 0.02` admits only oscillations below 1 rad/s, and any
oscillation that both fills the attitude band and completes a cycle inside the
2.000 s window needs `w >= pi rad/s` and would show `max|omega| >= 0.063 rad/s`,
three times the limit. The smallest band oscillation the clause rejects has
amplitude 0.0064 rad, a third of the attitude band.

The limitation: the rate clause does not bind on any run in this campaign, at any
loss level up to `p = 0.70`, or at any loop delay up to the 13-tick margin (max
`|omega|` in the window is 1.944e-06 at `D_eff = 13` and 5.48e-04 at `p = 0.70`).
It is a guard against a failure mode this plant and controller do not exhibit. It
costs nothing and it closes the hole the mandate named.

### The release predicate

Scenario `sim/scenarios/S2-gust.json`, seeds 1 through 200, loss model
independent Bernoulli per packet event with `p_up = p_down = 0.30` drawn from
separate named streams, both directions impaired, loop delays `D_eff = 0` and
`D_eff = 1`. 400 runs. All five clauses must hold on every run.

1. **Termination.** The episode reaches tick `T-1` with `sim_reason = 1
   SIM_HORIZON` and the vehicle-side reason 1 STABILIZED. Never `sim_reason` 2 or
   3, never vehicle reason 2, 3 or 4. Clauses 2, 3 and 5 are evaluated offline on
   the simulator's truth trajectory and are authoritative; the vehicle's own
   verdict is recorded beside them as `settle_agreement`.
2. **Peak.** `max |theta| <= 0.15 rad` over every recorded row of the episode,
   terminal row included.
3. **Settled.** `|theta| <= 0.02 rad` and `|omega| <= 0.02 rad/s` on every tick
   of the final 1000 ticks.
4. **Cadence.** Exactly one actuator response for every scheduled control tick:
   one requested actuator command per tick in the `Trace`, coast and neutral
   ticks included. On the socket path the same clause reads as one type-5
   actuator datagram per vehicle cycle, and it is proved separately by
   `tests/functional/test_lockstep.py`. Ground commands are outside this clause:
   they are not per-tick and they cross no impaired link.
5. **Finiteness.** No NaN and no infinity in `theta`, `omega`, `delta`,
   `i_state`, `d_prev` at any tick.

Changed from the prior draft on clauses 1, 2 and 4. Clause 1 required "the
simulator's authoritative outcome is stabilized", which is an outcome the sim's
enum does not contain and which contradicted the same section's rule that the
offline predicate is authoritative. Clause 2's peak is now defined over every
recorded row including the terminal one, which is why the `p >= 0.50` cells below
read above 0.30. Clause 4 counted actuator frames, which the command that
produces the 400/400 cannot see: `sim.run_headless` has no wire.

Pass is 400/400. Anything less is a release failure, not a flaky test. The
0.15 rad peak clause belongs to this campaign, not to every scenario:
S5-overgust peaks at 0.1514 rad by design at `p = 0` and is a stress row.

The loss model covers the sensor and actuator directions only. Ground commands
ride a different path with no stochastic fault model in v0.2b, and no wording
anywhere may imply otherwise.

## Evidence tiers and versioning as applied in v0.2b

The three evidence tiers and the identifier grammar are project policy and live
in `docs/engineering-plan.md`. This section says what v0.2b puts in each tier and
which identifiers it instantiates.

### Tier assignment

**Tier 1, exact deterministic evidence.** Bit identity is asserted and proved by
a digest. v0.2b puts here: the wire encoding and the frame corpus, the RNG
known-answer tables, the controller arithmetic in the fixed operation order, the
episode state-machine transitions, the fixed-backend lockstep goldens
(same toolchain, with image digest and ISA recorded), and the per-run
trajectories and digests of the loss campaign.

**Tier 2, numerical equivalence within declared tolerances.** v0.2b ships nothing
here and names one boundary: cross-ISA comparison of vehicle-side goldens is
tier 2, which is why that claim is same-toolchain while the sim-side claim is
cross-platform on the no-libm condition.

**Tier 3, statistical reproducibility.** v0.2b puts here: the 400/400 pass rate
as a statement about 30% loss, the paired L7/L8 timing comparison, and every
percentile in `docs/results.md`.

The loss campaign is split across two tiers on purpose. Its per-run trajectories
and digests are tier 1, because each run reproduces bit for bit from its
committed seed. Its 400/400 pass rate is tier 3, because 400 samples are a
predeclared seed range and not a bound on the space of 30% loss sequences.
Changed from the prior draft, which assigned the whole campaign to tier 3 while
wording its `docs/results.md` sentence in tier-1 identity language.

A percentile is an observation over a stated cycle count in a stated environment.
Write "p99.9 observed 16.5 us over 2.7M cycles". Never "worst case", never
"guarantee" anywhere near a percentile, never a percentile with no denominator.

### The measurement invariant, as v0.2b applies it

The invariant in `docs/engineering-plan.md` reads: published timing evidence
comes only from qualified bare-metal execution, and containers, hosted CI,
lockstep, Macs and development machines prove function and produce no publishable
timing claim. Its compliance test, as v0.2b implements it:

> Every published number traces to a summary whose mode is `harness` or
> `freerun`, taken on the qualified bare-metal machine, that the discipline gate
> accepts; any container, CI, Mac or `lockstep` summary in the chain fails it. A
> committed baseline summary written before the field existed classifies as
> `harness (legacy)` and is admitted as `harness`; that is a gate
> classification, not a mode a binary can emit. A closed-loop timing claim
> (served s2a, discard age, L8) also requires `"mode": "freerun"` on top of that.

The qualifying condition is the machine and its applied configuration. The mode
field says which workload produced the number: `harness` is the published

### Identifiers instantiated by v0.2b

The grammar is `<word>(-<word>)*-v<integer>`, lowercase ASCII, hyphen separated,
no dots, no underscores, no dates, and it lives in the engineering plan. The six
instances are this release's contract:

| category | v0.2b instance | names |
|---|---|---|
| model | `pitch-frozen-flight-v1` | plant equations, state variables, integrator, units, sign conventions |
| controller | `pid-v1` | controller form, gains, limits, operation order, anti-windup rule |
| actuator | `ideal-angle-v1` | requested-to-applied mapping and its limits |
| sensor | `ideal-v1` | truth-to-observation mapping and its rejection rules |
| environment | `frozen-flight-v1` | the constant flight condition supplying `Environment.k_a` |
| scenario schema | `tvc-scenario-v1` | the field set and validation of a scenario file |

The wire payload versions are `telemetry_v1`, `command_v1`, `ack_v1`,
`sensor_v1`, `actuator_v1`, `control_v1`, each with its own schema string and
CRC-32C above. A change to the field set, order, offsets, sizes, endianness, or a
field's meaning changes the schema string and the hash, which is exactly when the
version bumps; assigning meaning to a reserved flag bit does not.

Historical evidence keeps the identifiers it was recorded with. A re-run under
new identifiers is a new result beside the old one, never a replacement.

The six reproducibility fields the engineering plan requires are all here: model
version (the `identifiers` block), scenario version (`scenario` plus
`scenario_sha256`), seed, named RNG streams with their start states, the resolved
parameter block as used, and the toolchain. `summary.json` carries the same
`identifiers` block so a vehicle-side summary can be checked without the sim's
file. The pairing rule is the `<label>` prefix plus the digests: `replay.json`
names the sha256 of every file in the set, so a recording that does not hash to
its `replay.json` entry is not the recording that `replay.json` describes. A
recording without its `replay.json` is unidentified evidence and is not
published, which is the engineering plan's reproducibility contract stated in
this release's file names.

The identifiers ride once per run, not in every record: the control record is
fixed at 128 bytes and the hot path writes no identity strings. The recording
header stays version 1 with its `schema_hash`, its reserved u16 at offset 10 zero
and available to a future header version carrying a run id. v0.2b does not spend
it.

`<outdir>/<label>.inputs.tvcrec` holds every sensor frame the sim sent, verbatim,
post-loss, in send order, each appended once at build time, behind the 32-byte
header with zero timestamps in lockstep. A replay-grade run requires
`telemetry.dropped == 0`, which the runner asserts.

### Golden format

Both CSVs are written after the run by `scripts/golden_csv.py`, called from
`scripts/run_scenario.py`: the vehicle CSV from `<label>.control.tvcrec`, the sim
CSV from the sim's in-memory `Trace`. The vehicle process formats nothing.
Columns, header row, doubles as 16 lowercase hex digits with `0x`
(`struct.pack("<d", x)`), no decimal floats anywhere:

```
vehicle: tick,state,reason,sensor_tick,staleness,ladder,theta_bits,omega_bits,cmd_bits,i_state_bits,d_prev_bits
sim:     tick,has_sample,applied,theta_bits,omega_bits,cmd_applied_bits
```

`ladder` is `flags & 0x1D` (FRESH_SAMPLE, CMD_APPLIED, COAST, NEUTRAL): the bits
that depend on syscall outcomes (TX_OK, RX_OVER_BOUND) stay in the recording and
out of the golden. Sim row k holds the sampled state that went on the wire, so
for every row with `has_sample` the sim's `theta_bits` equals the vehicle's, and
`test_lockstep` asserts it.

`scripts/golden_csv.py` gains `--columns` so a caller can extract a named subset;
the harness-workload fixture uses `--columns tick,theta,cmd`.

`tests/golden/lockstep/manifest.json` carries one entry per scenario at its
scheduled length, with `sim_csv_sha256`, `vehicle_csv_sha256`, `inputs_sha256`,
`reason`, `reason_tick`, `outcome`, `consumed_ticks` and `toolchain` (image digest,
g++ string, ISA). Every scenario, demo-loss30 included, runs at full length in CI
and compares digests. Committed per-tick CSVs, for diagnosis: S4-open,
S6-blackout and S7-abort in full, plus the first 2000 rows of S2-gust and
S5-overgust. Lockstep is tick-indexed and deterministic, so the first 2000 rows
of a full run equal a 2000-tick run's rows and a digest mismatch localizes against
the committed prefix without committing 10000-tick files.

Digests are `hashlib.sha256` over file bytes, lowercase hex. CRC-32C stays the
wire's integrity primitive.

### Same-toolchain rule

`docker/Dockerfile:1` is `FROM ubuntu:26.04`, a floating tag. Capability 5b pins
it by digest and records the digest and the ISA in the lockstep manifest. A
digest pins the image index, not the ISA: the Mac's container is aarch64 and
hosted CI is x86-64.

- Vehicle-side golden: same toolchain only, meaning the pinned container or the
  qualified machine's g++.
- Sim-side golden and the Python reference controller: bit-identical across the
  Mac, the container and the qualified machine, on the no-libm condition.

`-ffp-contract=off` moves from `CMAKE_CXX_FLAGS_RELWITHDEBINFO`
(`CMakeLists.txt:19`) into `add_compile_options(-ffp-contract=off)` placed after
`FetchContent_MakeAvailable(hdr_histogram)` at `CMakeLists.txt:34`, so an explicit
`-DCMAKE_BUILD_TYPE=Debug` or `Release` build gets it too and the vendored
HdrHistogram build does not. Every lane the project builds today already gets the
flag through `CMakeLists.txt:12-14` and `:19`, which force `RelWithDebInfo` when
no build type is given; this closes the case nobody builds yet. Changed from the
prior draft, which justified the move by claiming a plain build lacked the flag.

### Replay execution, out of scope

Replay execution needs nothing v0.2b does not write: `inputs.tvcrec` fed to the
vehicle in place of a socket, the original `vehicle.csv` and its digest, and
`replay.json` for config, seed, initial state and identifiers. It is not built in
v0.2b.

## CI and bare-metal acceptance

### The simulation kernel as a headless API

`sim/` is layered and the layering is enforced by a test rather than by
convention.

**Layer 0, pure**: `rng.py`, `fixmath.py`, `plant.py`, `actuator.py`,
`sensor.py`, `environment.py`, `control_ref.py`, `episode.py`. No import of
`socket`, `time`, `os`, `pathlib`, `random` or `math`. Every function takes state
and inputs and returns new state.

```
truth_next      = plant.step(truth, applied, environment, disturbance, dt)  -> TruthState
act_next        = actuator.step(act, arriving, dt)                          -> ActuatorState
observation     = sensor.observe(truth)                                     -> Observation
u, ctrl_next    = control_ref.step(ctrl, observation)                       -> (float, ControlState)
ep_next, reason = episode.step(ep, inputs)                                  -> (EpisodeState, reason)
```

**Layer 1, orchestration**: `link.py` (the loss decision, still pure: stream in,
bool out), `scenario.py` (reads a JSON file and resolves it into a frozen
parameter set), `trace.py`.

**Layer 2, transport**: `run_sim.py` alone. It is the only module that imports
`socket` or `time`.

`sim/run_headless.py` runs one scenario in-process:

```python
run_headless(scenario, *, seed, delay_ticks, controller=control_ref) -> Trace
```

No sockets, no subprocesses, no files, no clock reads. It executes the lockstep
recurrence with the Python reference controller in place of the vehicle process
and returns a `Trace`: per tick, `TruthState`, `Observation`, requested command,
`ActuatorState`, applied gimbal, episode state, reason, and the loss decisions,
plus the terminal `sim_reason`. `Trace.to_sim_csv()` emits the same bytes the
socket path writes, so the release predicate is evaluated on either.

Two consumers in v0.2b: the release predicate, which runs 400 in-process
simulations with no vehicle process and no port allocation, and a
cross-implementation test asserting that `run_headless` at `D_eff = 0` produces
the same sim CSV as the socket lockstep run driving the C++ vehicle, for every
scenario.

The C++ half of the same invariant: `src/control.hpp` and `src/episode.hpp` are
pure functions of their inputs, with no globals, no clock reads and no sockets.

```cpp
double control::step(control::State& s, const Observation& obs) noexcept;
episode::Transition episode::step(const episode::State& s, const episode::Inputs& in) noexcept;
```

`episode::Inputs` carries `expected`, `staleness`, `fresh`, `theta`, `omega`,
`sim_reason`, `episode_end`, the classified command, `auto_arm`,
`horizon_reached` and `peer_refused`. Nothing inside calls `now_ns()`.

Enforcement: `tests/unit/test_sim_layering.py` imports each Layer 0 module in a
subprocess with `socket`, `time`, `os`, `pathlib`, `random` and `math` replaced
by raising stubs in `sys.modules`, then calls one step function from each.
`tests/unit/test_sim_purity.py`'s grep stays beside it: the grep catches a
transcendental, the stub catches an I/O import the grep would miss.

Explicit non-goals: no plugin registry, no abstract base classes, no dependency
injection, no batched entry point, no campaign runner, no parameter sampling. The
seams are the five function signatures and the six data types.

### CI proves structure, bare metal proves timing

Removed from the prior draft, because mandate correction 12: the assertion that
"every call on an empty socket returns under 1 ms". Hosted runners are Azure VMs
(`.github/workflows/ci.yml:15-17`) and that assertion measures the runner. No
test under `tests/` asserts on any duration.

**1. The descriptor is nonblocking.** `tests/cpp/net_tests.cpp` calls
`net::open_udp()` and asserts `(fcntl(fd, F_GETFL) & O_NONBLOCK) != 0` for the
sensor socket and the command socket. The sockets are created with
`socket(AF_INET, SOCK_DGRAM | SOCK_NONBLOCK, 0)`, so the assertion checks the flag
actually reached the descriptor.

**2. An empty receive returns EAGAIN or EWOULDBLOCK.** A receive on a freshly
bound socket with nothing queued returns -1 and `errno` is `EAGAIN` or
`EWOULDBLOCK`. The test accepts either spelling. No timing assertion accompanies
it.

**3. The hot-path receive uses MSG_DONTWAIT.** Proved by a compile-time constant
plus a gate, not by a test double.

```cpp
// src/net.hpp
inline constexpr int kHotRecvFlags = MSG_DONTWAIT;
inline constexpr int kHotSendFlags = MSG_DONTWAIT;
// recv_batch and send_frame take no flags parameter and have no overload that does.
```

`scripts/check_nonblocking.py`, stdlib, invoked from `tests/ci.sh` beside the
existing style gate (`tests/ci.sh:5-8`), asserts three things and exits 1 naming
the file and line on any failure:

- every occurrence of `recvmmsg`, `recvmsg`, `recvfrom` or `recv(` under `src/`
  is inside `src/net.cpp`;
- inside `src/net.cpp`, every such line either contains `MSG_DONTWAIT` or
  `kHotRecvFlags`, or sits inside a function on an explicit allow list
  (`net::recv_blocking`, used only for the lockstep receive and the free-run
  origin wait);
- the body of `run_freerun`, from its opening brace to the next top-level
  function, contains no call to `net::recv_blocking`, `poll`, `select`, `epoll`,
  `SO_RCVTIMEO` or `sleep`.

`tests/unit/test_check_nonblocking.py` pins the checker against fixture files
that should pass and should fail, so the gate cannot rot into a no-op. The
downside, named: a lint is not a proof and an alias or a macro defeats it. It is
paired with the runtime `O_NONBLOCK` assertion and with capability 6's review
gate.

**4. No blocking receive is reachable in the free-run cycle.** Structural, from
the two-loop split: `run_freerun` and `run_lockstep` are separate functions in
separate translation units, and every blocking receive lives in `run_lockstep` or
in the pre-loop origin wait. Check 3's third clause is the mechanical proof. The
alloc guard (`--alloc-guard=abort`) covers allocation and needs no change.

### Runs are the timing experiment unit

Removed from the prior draft, because mandate correction 9: the exact two-sided
binomial test on pooled cycle exceedance counts at 15, 20 and 30 us, and the
exact Mann-Whitney U rule with its `U > 13` threshold. Wakeup events cluster, so
2.4M cycle observations are not 2.4M independent experimental units.

The **interleaved run** is the experiment unit. The campaign is
`--only L5 L7 L8 --repeat 8 --interleave --cycles 300000 --cpu 7`, which yields
8 interleaved L7/L8 pairs, each pair measured minutes apart under the same
machine state.

`scripts/compare_arms.py --results <dir> --a L7 --b L8`, stdlib, deterministic
output:

```
pair   L7 p99.9   L8 p99.9   diff
   1     16.383     16.671   +0.288
   ...
   8     16.295     16.703   +0.408

median diff +0.31 us   min -0.06 us   max +0.74 us
practical margin +2.00 us (predeclared)   verdict: within margin
sign test (supplemental): 6 of 8 differences positive, two-sided p = 0.2891
```

**The predeclared practical margin: 2.0 us absolute.** Absolute, not a
percentage: at a 16.5 us floor a percentage is noise about a small number.
Justified from the committed baselines (probe over
`baselines/2026-08-29-pinned-timer-campaign`):

| level | p99.9 over three repeats, us | spread |
|---|---|---|
| L4 | 15.991, 16.495, 16.367 | 0.504 |
| L5 | 16.351, 16.543, 16.831 | 0.480 |
| L6 | 17.615, 17.263, 16.655 | 0.960 |

Run-to-run spread at the pinned-timer floor is 0.5 to 1.0 us at identical
configuration. 2.0 us is about twice the largest observed within-level spread and
about 12% of the 16.5 us floor, four times tighter than the L5 gate's 50%
tolerance (`scripts/bench_gate.py:60`). The same campaign's published cost shows
the margin detects something rather than passing everything: L6 minus L5, paired
by repeat, is +1.264, +0.720, -0.176 us, median +0.720, which is the telemetry
cost the README reports as 4% at the tail. Named downside: those three baseline
repeats were not interleaved, so their spread mixes run-to-run variation with
drift over the campaign. Capability 9 reports the observed pair spread beside the
margin so the next release can re-declare it from interleaved data.

**The sign test is supplemental.** Exact two-sided sign test on 8 pairs (probe):

| pairs sharing a sign | two-sided p |
|---|---|
| 5 of 8 | 0.7266 |
| 6 of 8 | 0.2891 |
| 7 of 8 | 0.0703 |
| 8 of 8 | 0.0078 |

With eight pairs the sign test cannot reach alpha 0.05 unless every difference
shares a sign. It is reported, never used as the release rule, and
`docs/results.md` prints that table next to the result so nobody reads a p of
0.29 as evidence of no effect.

**The release decision**, two predeclared clauses:

1. the practical paired effect: median L8 minus L7 p99.9 at or under +2.0 us;
2. the existing benchmark discipline:
   `scripts/bench_gate.py --results <dir> --level L5` exits 0, median p99.9 at or
   under 24.8 us against `baselines/2026-08-29-pinned-timer-campaign` at the 50%
   tolerance (`scripts/bench_gate.py:60`), with `discipline_problem` clean on
   every summary in the directory.

`compare_arms.py` exits 1 when the median difference is above the margin, which
fails the release clause, not the publication. A null or very small cost is
publishable. A measurable regression is publishable when it is reported with its
number, and the verdict goes into `docs/results.md` either way. Changed from the
prior draft, which called a measurable regression publishable in one paragraph
and made it a campaign failure in the next.

### Sweep levels

L0 through L6 are untouched, so the published L6 row keeps its meaning. Two new
cumulative levels in `scripts/sweep.py`, with `LEVELS` entries becoming 4-tuples
carrying a `peer` field (`None` for L0 through L7):

```python
("L7", "+ control record (128 B)", ["--telemetry", "--record=control"], None),
("L8", "+ sensor and actuator sockets, PID, episode machine",
 ["--mode=freerun", "--auto-arm", "--telemetry", "--record=control"],
 "python3 -m sim.run_sim --mode=freerun --scenario=S1-hold --seed=1 --loss=0.0 "
 "--ticks={total_plus_margin} --vehicle=127.0.0.1:{sensor_port} --bind-port=0"),
```

Writing the peer's command line into the table is what makes the L8 row
self-describing: the served-coverage clause is evaluated only against a peer at
`--loss=0.0`, and a row whose peer loss is nonzero is timing evidence and never
coverage evidence. Changed from the prior draft, which described L8 only by its
vehicle flags and left the peer's scenario, seed and loss unstated.

`tests/unit/test_sweep.py:13-14` updates from the L0..L6 chain to L0..L8 in the
same PR. The `plan_levels` assertion at `tests/unit/test_sweep.py:8` is
unaffected, because L4 still stops the chain without `--cpu`. `plan_levels`
raises on a level whose flags contain `--mode=lockstep`.

`--interleave` orders the runs as `for repeat: for level:`, and the flag lists
must be precomputed before either loop, because `scripts/sweep.py:220-231` builds
one mutable list and appends each level's flags while walking the levels in order:

```python
plans, flags = [], []
for label, desc, add, peer in runnable:
    flags = flags + [f.format(cpu=args.cpu) for f in add]
    if not args.only or label in args.only:
        plans.append((label, desc, list(flags), peer))
order = ([(r, p) for r in range(1, args.repeat + 1) for p in plans] if args.interleave
         else [(r, p) for p in plans for r in range(1, args.repeat + 1)])
```

Swapping the loops without precomputing appends every level's flags once per
repeat, so repeat 2's L5 command line would carry L0 through L8's flags twice.

The sweep launches the L8 peer itself (stdout to `<label>.peer.log`; peer death
breaks the chain like a skipped level) and does not call the runner. The sim runs
SCHED_OTHER on the housekeeping CPUs; `isolcpus=domain,managed_irq,6,7` keeps it
off the isolated pair.

## Ground station and demo

### The drain owns the UDP sink and the command socket

`telem::Drain::run()` already frames every record into a stack buffer and writes
it. The sink is one more line in that loop: `send(sock_, frame, len, 0)` on a
connected nonblocking socket when `--ground` is given. The file stays the record
of truth; a write failure is still exit 4. `EAGAIN` drops the datagram and counts
it, drop-newest like the ring. At 500 Hz the sink moves 142-byte frames, 71 KB/s,
well under the default loopback `SO_SNDBUF`. Socket or `connect` failure at
startup is exit 2 with `applied.ground = false`; every delivery error after that
is counted in `summary.json`'s `"ground": {"sent", "send_errors", "last_errno"}`
and is never fatal, because an absent listener must not fail a run.

The drain also owns the command socket: it validates the datagram, pushes the
decoded `(cmd_seq, opcode, effective_tick)` into the 64-slot drain-to-control
ring, and stores the source address. The control thread's per-cycle cost on the
no-command path is one relaxed load of the ring head. The drain's idle path is
`poll(cmd_fd, POLLIN, 1)` rather than a 1 ms sleep, so a command wakes it at
once. Cost: up to 1 ms of command latency. In lockstep the command socket is not
opened. The ring pattern extends `tests/cpp/ring_stress.cpp` to both
instantiations and both directions under TSan; this is the release's one new
concurrency shape.

### Station

`python3 -m ground.station`, one process, one thread, `select.select` over the
telemetry socket, the command socket and stdin. Stdlib plus `ground.wire`. No
curses, no live plotting. Refresh 10 Hz on a TTY, one `key=value` line per second
otherwise. Percentiles from a bounded deque of the last 5,000 records.

The station's stdin grammar gains one word beside `a`, `l`, `x`, `q` and
`--script`: `peer HOST:PORT` sets or retargets the command destination.

Command uplink, free-run only: on an operator action take the next `cmd_seq`
(from 1 per session), set `effective_tick = last_seen_tick + 50`, send, and
resend the identical payload every 20 ms until an ack with that `cmd_seq` arrives
or 10 sends have gone out, then show it unacknowledged and stop. Flags
`--retry-ms=20 --retries=10 --effective-margin-ticks=50`. The retransmit is
justified by the at-least-once uplink contract and by kernel-buffer drops, not by
a loss model: `link_sim` never touches this path. At-least-once means
"unacknowledged" is a status line, never a rollback. One station process per
vehicle run; restart both, since a second session's `cmd_seq` restarts at 1 and
the dedupe rule reads it as stale.

Recording: `<label>.ground.tvcrec` (header plus each telemetry datagram verbatim)
and `<label>.commands.jsonl` (one object per command sent and ack received).
`--script FILE` is the only scripted form, one `<seconds-from-start> <opcode>`
per line.

## Appendix A (informative): neglected terms and external comparisons

Nothing in this appendix is normative. No equation, constant, gate, predicate or
identifier above depends on any number here. It exists so a reader can size what

document makes, with its derivation and its assumptions written out rather than

### A.1 The flight-path rotation that freezing `gamma` discards

Assumptions: the parameters of record above; the lateral force taken at the
largest excursion the v0.2b scenarios reach; a point mass of `m = 3.0 kg`; small
angles, so `gamma_dot = a_lat / V`.

The two lateral forces add rather than cancel. A positive gimbal deflection puts
an upward force at the nozzle station behind the CG, and a positive angle of
attack puts an upward normal force at the CP ahead of the CG. The moments oppose,
which is the whole control mechanism; the forces do not.

    F_gimbal   = F * sin(DELTA_MAX)  = 60.0 * sin(0.12)        = 7.183 N
    F_normal   = q*S*C_N_alpha*alpha = 34.636059 * 0.08        = 2.771 N
    a_lat      = (7.183 + 2.771) / 3.0                         = 3.318 m/s^2
    gamma_dot  = 3.318 / 60.0                                  = 0.0553 rad/s

Integrated over the S2-gust episode the neglected rotation is 0.0100 rad, half
the settle band and 15% of the peak attitude excursion, because the gust
deflections partly cancel (probe: `python3 probe.py extras`, `python3 probe.py
gamma`). Both figures are design probes over the equations in this document.

Changed from the prior draft, which reported 1.5 m/s^2 and 0.5 rad: the 1.5
figure subtracted two lateral forces the sign conventions make additive, and the
0.5 rad figure was 50x the integrated value.

### A.2 One external estimate of the center of pressure

Method: Barrowman's slender-body procedure for the normal-force distribution of
an unfinned body of revolution, in J. S. Barrowman, "The Practical Calculation of
the Aerodynamic Characteristics of Slender Finned Vehicles", M.S. thesis, The
Catholic University of America, 1967.

Assumptions the method carries, all of which this comparison inherits: small
angle of attack, attached potential flow, incompressible and subsonic, a slender
body of revolution, no fins, no body-lift correction, and no base or viscous
contribution. Under those assumptions the nose contributes `C_N_alpha = 2.0` per
radian referenced to the body cross-sectional area, with its center of pressure
at a fixed fraction of the nose length, 0.466 for a tangent ogive; a
constant-diameter cylindrical section contributes no normal force at all.

One assumption is added here and appears nowhere else in this document: a 0.30 m
tangent-ogive nose on the 1.2 m body. The parameters of record do not specify a
nose shape, because nothing in the model reads one.

    x_cp   = 0.466 * 0.30                          = 0.1398 m from the nose
    l_arm  = x_cg - x_cp = 0.60 - 0.1398           = 0.4602 m
    k_a    = q*S*C_N_alpha*l_arm = 34.636059*0.4602 = 15.94 N*m/rad
    pole   = sqrt(k_a/J) = sqrt(15.94/0.36)        = 6.65 rad/s

Against the 9.0 N*m/rad and 5.0 rad/s of record. The two differ because `x_cp` of
record was inverted from a target pole, not estimated from a geometry.

What this comparison does not support: any statement about how a real airframe of
this shape behaves. The method above covers an unfinned nose in attached
potential flow, the nose shape is assumed here rather than specified, and this
project has flown nothing and validated nothing against flight data. It is one
arithmetic path to a comparable number, shown so the inversion in "Where `k_a`
comes from" can be checked, and it is not a fidelity claim.
